### Main process

- **Never-travelling folders** (in `gitService.ts`) — `neverTravelPaths()` (the layout's `never_travels`, parsed by `parseLayout` from `shared_remote.never_travels.paths`; `NEVER_TRAVELS_FALLBACK` for a workshop `.cinna-kit/` older than 1.8.0, `NEVER_TRAVELS_FILES_FALLBACK` for one older than 1.9.0), applied only when the remote is a Cinna library (`isCinna(auth)`). It covers the exclude block, `untrackNeverTravels()` in `commitAll`, `dropNeverTravelsFromUnsent()` → `rewriteUnsent()` before the push in `shareChanges` and `initWithRemote`, `rewriteUnsent()` before the rebase in `pullRebaseClean` and again after a `non_ff` retry's Update in `push`, and `restoreLocalOnlyFolders()` after Get. `preflightShare` and `initWithRemote`'s guard only check. ## Database Schema

None. Whether an agent is shared comes from each folder's `origin` and from `libraryService`'s in-memory cache, and a restart lists the library again. Outside the database:

- `<userData>/team-library-trust.json` (`libraryTrust`): `{gitOrigins: {<instance origin>: [<git origin>…]}, pending: {<instance origin>: {<slug>: <repo id>}}}`. The instance's own origin is never written to it. It is written atomically (temp file, fsync, rename). A failed write is logged, and the list still holds in memory for that run. A host with no `userData` keeps it **in memory only**, never in a shared fallback such as the temp directory, where any local user could plant a trust list
- `cinna.server` in each shared folder's `.git/config`: the instance's API origin, written after Get and after Share with the team once `.git` exists
- `shared_remote` in each shared folder's `app-data/desktop.json`: `{kind, repo_id, clone_url}`, written and cleared by `writeLocalLink` and never read for a decision

## IPC Channels

Every handler calls `userActivation.requireActivated()`, runs in the settings scope (folder agents are machine-local) and reads the active **profile** itself for the token and the library. Only ids cross; no path ever arrives from the renderer. Each resolves a `SharingOutcome<T>`: refusals travel inside `value` as `ShareRefusal` codes, and `success: false` carries only what no surface can show as a state — `reauth_required` (which `_wrap` turns into the app-wide prompt) and a coded `DomainError` such as `not_found`. Anything else throws. The `catalog.ipc.ts` convention.

| Channel | Signature |
|---|---|
| `sharing:statuses` | `() → AgentShareStatus[]` — every shared agent, no network |
| `sharing:status` | `({agentId, fetch?}) → AgentShareStatus \| null` — null when not shared |
| `sharing:draft-message` | `({agentId}) → string` — AI summary, `''` on any failure |
| `sharing:share-changes` | `({agentId, message}) → AgentShareResult` |
| `sharing:update` | `({agentId}) → AgentShareResult` |
| `sharing:use-team-version` | `({agentId}) → AgentShareResult` — `agentId` in the result is the kept copy; on success the handler calls `acpProcessPool.retire(agentId)` |
| `sharing:share-with-team-draft` | `({agentId}) → ShareWithTeamDraft` |
| `sharing:share-with-team` | `({agentId, name, people}) → AgentShareResult` — `people: {userId, access}[]`; the description is the manifest's, never taken from the renderer |
| `sharing:people` | `({agentId}) → AgentPeopleDto \| null` — null when the active profile cannot speak for the entry (not shared, `external`, another account's, or a `404`) |
| `sharing:set-people` | `({agentId, people: LibraryGrantInput[]}) → SetPeopleResult` — the whole list; `people` in the answer is the server's |
| `sharing:search-people` | `({query}) → PersonSearchResult[]` |
| `sharing:history` | `({agentId}) → AgentVersionDto[]` — `[]` when not shared |
| `sharing:unshare` | `({agentId, deleteFromLibrary}) → AgentShareResult` — `deleteFromLibrary` is taken only as a literal `true` |
| `sharing:library` | `({refresh?}) → LibraryListingDto \| null` — null for a non-Cinna profile |
| `sharing:get` | `({repoId}) → AgentShareResult` — `agentId` is the new row |
| `sharing:changed` | main → renderer event, no payload |

`AgentShareResult` carries the status after the attempt, so the surface needs no refetch. On a successful Use the team's version its `detail` names the per-machine files that could not be copied. After a successful Get, Update that moved the folder, or Use the team's version, `autoAttached` lists `{slot, credentialName}` for each credential main attached and `setupNeeded` says Finish setup should open: after a Get, any required slot unsatisfied; after an Update or Use the team's version, a required slot unsatisfied that was not before the verb. Every other result carries `[]` and `false`.

## Services & Key Methods

### `libraryService`

- `refresh(userId)` — `cinnaFetch('/api/v1/library')`; `404`/`403` → empty listing with `available: false`, logged once per host in `missingRoutesLogged`. `statusOf`'s `removed` and `removedFromLibrary` both require `available`, so a stand-in listing never reads as an entry deleted. other errors thrown. Every row's `clone_url` goes to `libraryTrust.learn(host, …)`. Publishes `sharing:changed` only when `signature()` (host + sorted `repoId:headSha:access`) moved. Overlapping refreshes are ordered per profile by a sequence taken at the start (`started`) and the one the cache holds (`applied`): an answer from a refresh older than the cached one is dropped (no cache write, no publish) and its caller gets the cached, newer listing — never one that started before it did. Not coalescing, which could hand a caller an answer from a request that started before it asked
- `refreshQuietly(userId)` — for timers; on `reauth_required` it stops the poll (activation after the re-auth restarts it). A `generation` counter drops the result of a refresh that outlived a `stop()`
- `cached(userId)` — the listing only while its host is still the profile's server; a profile re-pointed elsewhere does not keep the old host's agents
- `knownHosts()` — origins of **every** Cinna profile on the machine; with `libraryTrust` (git origins an instance named) and the folder's `cinna.server`, what makes a remote `cinna` rather than `external`. Whether its token may be used is `authFor`'s separate question

### `sharingService`

- `locateKit` / `locateShared` — through `localAgentService.locate`; a kit agent whose real parent is the root's `Local/`, then `gitService.readShareRemote` for own-repo + `origin`
- `authFor(shared)`: `external` means the user's own git. A `cinna` remote on the active profile's host gives `{kind:'cinna', origin: <git origin of originUrl>, token: () => getCinnaAccessToken(profile)}`, but only after `libraryTrust.trusts(host, gitOrigin)` passes a second time. Otherwise it falls back to `external`. A `cinna` remote on another host gives `'other_account'`, and the caller reads counts with no network
- `statusOf` — first `recoverLocalOnlyFiles`: when `hasLeftoverLocalOnlyFiles`, takes the turn lock (skipped while anything holds it — never mid-action) and `restoreLeftoverLocalOnlyFiles`. `shareChanges`, `useTeamVersion` and `unshare` call `restoreLeftoverLocalOnlyFiles` right after taking the lock; `update` gets it from `pullRebaseClean`. Then `removed` when the remote is `cinna`, its host's listing is loaded with `available: true` and lacks the repo (no fetch then); otherwise `readShareStatus` with the listing's `headSha`
- `shareChanges`, `update` — turn lock (`turnLock.acquire(agentId, 'sharing')`, `turn_in_progress` on contention), then `gitService.shareChanges` / `pullRebaseClean`; on success re-list the library and publish (`update` also rescans the root and, after releasing the lock, runs `credentialSetup`). `pullRebaseClean` reports `done` only when the folder was behind, so an Update with nothing to bring attaches nothing
- `credentialSetup(userId, agentId, before?)` — `serviceCredentialService.autoAttach(agentId)` (never throws), then `missingSlots` (names of slots with `!satisfied`; optional slots are always satisfied; an unreadable agent is `null`, reading as nothing needed). `setupNeeded` is true when a missing slot is not in `before`; with no `before` (Get, or a `before` read that failed), when anything is missing. `update` and `useTeamVersion` take `before` with `missingSlots` under the turn lock, before git runs. Run at the end of `update`, `useTeamVersion` (for the team's version, which keeps `agentId`) and `get`, each after the rescan so the slots are the new files'
- `useTeamVersion` — mints the token before anything moves; `freeMineDir`; rename; `gitService.clone`; `carryMachineFiles` (ignored paths minus `NOT_CARRIED`, `cpSync` with `force:false`; answers the paths it could not copy, which `missedDetail` puts — up to three, then "and N more" — in the result's `detail`); for a Cinna remote, `settleLocalOnlyFiles` with `keepLocalOnlyFiles(mineDir)` (a never-travel file the old folder still tracked was not ignored, so not carried; the team's tracked copy is overwritten); fresh id, `slug: basename(mineDir)` (else `manifest.slug.folder_mismatch` and two agents on one slug) and "(my copy)" via `writeManifest` while the copy still has `origin`; `freeMineDir` trims the base so `<base>-mine[-n]` stays within 63 characters; then `writeLocalLink(copy, null)`, `removeOrigin` and `excludeFromEnclosingRepo` on the copy. Any throw between rename and new id → `putBack` (a landed clone is renamed to `.<slug>.discard-<id>` before deletion — the scanner skips dot-folders — so a partial delete never leaves the original id at the path and never blocks the rename-back) and rethrow `CinnaReauthRequired`, else `failed`
- `shareWithTeam`: refuses without a Cinna profile, outside `Local/`, and on `git_missing`. It refuses `remote_exists` unless `removedFromLibrary` holds, meaning `origin` is a `cinna` remote of the active host that a fresh `libraryService.refresh` with `available: true` does not list. It then takes the turn lock (`turn_in_progress`); `gitService.preflightShare(dir, root, true)` (read-only) **before** the `POST`, so a refused folder leaves no library entry; `POST /api/v1/library/agents {slug, name, description, grants}` — `description` is always the manifest's (`shareWithTeamDraft`), `grants` the chosen people as `{principal: {user_id}, access}`, which core applies on create (a core older than that ignores them). `libraryTrust.learn` the answer's `clone_url` (refused when not acceptable: non-http(s), or plain http to a non-loopback host from an https instance) and `setPending(host, slug, repoId)`; on `409`, `unfinishedEntry` adopts only that pending repo id, still empty and maintained. Then the grants: an entry with no `maintainers` is refused `failed`; otherwise `PUT …/agents/<repo_id>/grants` with `initialGrants` (each maintainer as `maintain`, then each chosen person not already one), and any refusal from that write is `failed` with a sentence, before anything below runs. For a restart, `removeOrigin` + `writeLocalLink(dir, null)` only now, after the entry exists; `gitService.initWithRemote` with the header scoped to the git origin; `recordServer` and `writeLocalLink` whenever `.git` exists, sent or not; `clearPending` once sent
- `people(userId, agentId)` — `libraryTarget` (a `cinna` remote with a repo id whose `authFor` is the active profile's), else null; `GET …/grants` through `fromCoreGrants`, which reads a bare array or one under `grants` / `data`, a principal as `"everyone"` or an object with `user_id` / `role`, the name from `display_name`, `full_name` or `email` on the row or the principal, and drops a row it cannot place. `403` → `{visible: false, people: [], selfUserId: null}`; `404` → null; anything else throws. `selfUserId` from `selfIn`: `getStoredCinnaSubject(profile)` (the stored token's `sub`, no network), kept only when it is a user in the list
- `setPeople(userId, agentId, people)` — `parseGrantInputs` rejects the whole list on one malformed row (`failed`); `PUT …/grants` with `toCoreGrants`. The answer's `people` is `fromCoreGrants` of the `PUT`'s body, or a fresh `people()` when that is empty; then `refreshListing()` and `sharing:changed`, since the listing's maintainers and the caller's access may have moved. No turn lock: it writes nothing on disk
- `libraryWrite(profile, path, method, body?, goneIsDone)` — the one writer for grants and delete. A 2xx with no JSON (`invalid_response`) is a write that happened; `404` with `goneIsDone` is success; `403` is `no_access` rather than `cinnaFetch`'s `reauth_required` (a role, not a dead session); a real `reauth_required` still throws for the prompt; anything else is `failed` with the server's `detail`
- `searchPeople(query)` — under two trimmed characters, or a profile with no host, `[]` without a request; `GET /api/v1/users/search?q=…&limit=10`, rows from `data` (`id`, `email`, `full_name`, the name falling back to the email); `403` / `404` → `[]`
- `history(userId, agentId)` — `locateShared` then `gitService.readHistory`; `[]` when not shared
- `unshare(userId, agentId, deleteFromLibrary)` — `not_shared` without `locateShared`; turn lock (`turn_in_progress`); with `deleteFromLibrary`, `libraryTarget` (else `other_account`) and `DELETE /api/v1/library/agents/<repo_id>` through `libraryWrite(…, goneIsDone: true)`, a refusal returning before anything local; then `gitService.removeOrigin` (`failed` when git refused), `writeLocalLink(dir, null)`, `unsetCinnaServer` (a failure only logged). After the lock: `refreshListing()` and `settle` (rescan + `sharing:changed`). It never calls `refuseUnsharedChanges`
- `library(userId, refresh)` — the cached or refreshed listing joined to this machine: `localCopies` maps by repo id (from `origin`) and by manifest id; `updateAvailable` from `isBehindLibrary`
- `get(userId, repoId)` — listing (refreshed once on a miss) → `not_in_library`; `SLUG_PATTERN`; `libraryTrust.learn` the `clone_url` (refused when not acceptable); `exists` on slug or manifest id; clone into the **agents home** (`agentsHomeService.requireRoot`); `recordServer`; `restoreLocalOnlyFolders`, `settleLocalOnlyFiles(target, new Map())` (a never-travel file the team's version carries becomes the template's) and `writeLocalLink` (a failure there is logged, not a refusal); re-check the manifest id that arrived and remove the clone on a clash; rescan; `credentialSetup` with no `before`
- `teamChanges(userId)` — per shared Cinna agent, `teamChangeOf` (`readShareRemote` + `isBehindLibrary`). Each answer is memoised against the listing's host, fetch time and content plus `gitStateKey(dir)` — `HEAD`, the ref it names, `packed-refs` and `config` stamps read straight from `.git` — so a steady Inbox spawns no git. A worktree's `.git` file is not memoised

### `gitService` share verbs

- `run(..., extraEnv)` — the one runner both halves use; `extraEnv` is merged last and carries only `authEnv`
- `authEnv(auth)` — `GIT_CONFIG_COUNT=2`, `http.<origin>/.extraHeader = Authorization: Bearer <token>`, `http.followRedirects = false`. Called per network child (`runNet`), so each gets a freshly minted token
- `readShareStatus(dir, auth, fetch, libraryHeadSha?, cinnaRemote = isCinna(auth))` — `teamRef` is `origin/main`, else the upstream; ahead/behind by `rev-list --left-right --count`; with a library head not in history, `behind` is the count when the commit is present, else `-1`. `changedPaths` = untracked-not-ignored + `diff --name-only <merge-base>`, minus, when `cinnaRemote`, every never-travel path (`travelsNot`) — so a team version that still tracks `.claude/settings.local.json` never counts this machine's differing copy. `statusOf` reads with no auth and passes `remote.kind === 'cinna'` itself
- `shareStateOf(counts)` — `diverged` / `behind` / `unshared` / `up_to_date`; `other_account` and `removed` are main's
- `pullRebaseClean(dir, auth, identity, workshopRoot)` — for a Cinna remote, `restoreLeftoverLocalOnlyFiles` first, `ensureAgentExcludes` (so a put-back file is ignored), `keepLocalOnlyFiles` + `saveLocalOnlyBackup`, then `checkout HEAD -- <never-travel files HEAD tracks>` so an edited tracked copy is not `dirty`; after `bringInTeamChanges`, in `finally`: not done → a checked-out file that was absent before is removed; `putBackLocalOnlyFiles` with overwrite (template and `carried` = `trackedLocalOnlyFiles` only when done), and the backup dropped when every write succeeded. `bringInTeamChanges`: fetch; nothing behind → not done, no refusal; tracked edits or an untracked file on an incoming path → `dirty`; no local versions → `merge --ff-only`; else, for a Cinna remote, `rewriteUnsent` first, then `rebase --no-autostash`, aborted on failure → `diverged_conflict`
- `push` — `push -u origin HEAD:main`; `classifyPush` → `non_ff` (one `pullRebaseClean`, `rewriteUnsent` again for a Cinna remote, one retry), `no_access`, `push_rejected` (server's `remote:` lines as `detail`), `fetch_failed`. For a Cinna remote whose refusal is the server's policy (`refusedByPolicy`: `push_rejected` with `(pre-receive hook declined)` and not core's `MSG_UNAVAILABLE` — `POLICY_UNAVAILABLE`, *can't check this change right now*; `failed to lock` and other `[remote rejected]` reasons excluded), `sendCombined`
- `sendCombined` — refused unchanged on a detached `HEAD` or a failed fetch; when the team ref is not an ancestor of `HEAD`, one `pullRebaseClean` + `rewriteUnsent` first. `combineUnsent`: `rev-list --no-merges <HEAD> --not <team ref>` (null, so the original refusal stands, with fewer than two); notes by `log -1 --format=%B`, newest first, de-duplicated; `commit-tree <HEAD>^{tree} -p <team ref>` with `commitFlags`; pinned at `refs/cinna/combined-<hex>` (`update-ref <ref> <sha> ''`). `push origin <scratch>:refs/heads/main`; on success `update-ref <branch> <sha> <old HEAD>` (compare-and-swap; on a miss, `replayOntoCombined`: if the branch still descends from the old HEAD, `rebase --onto <combined> <old HEAD>` — the combined tree is the old HEAD's, so only the versions recorded since replay — aborted and logged when it stops) and `branch --set-upstream-to=origin/main`; `non_ff` → one more round, at most one Update; anything else is the answer. The scratch ref is deleted in `finally`
- `commitAll(dir, message, identity, workshopRoot, neverTravel)` — `guardSecrets(…, neverTravel, untrack: true)`, `add -A -- .`, `nothing_to_share` when nothing is staged, commit with `commitFlags` (`commit.gpgsign=false`; `user.name`/`user.email` only where git has none)
- `guardSecrets(gitPath, dir, workshopRoot, neverTravel, untrack)` — `ensureAgentExcludes`; with `neverTravel && untrack`, `untrackNeverTravels` (`rm -r --cached --ignore-unmatch` over `neverTravelPaths`), the only place anything is untracked; then `trackedSecrets` (`ls-files -z` against `isSecretFile` and `layout.desktopOwned()`), minus, with `neverTravel`, paths under the never-travel folders; `secrets_tracked` with up to three paths
- `ensureAgentExcludes` — the marked block (`# >>> Cinna Desktop: the agent kit's ignore rules …` / `# <<< Cinna Desktop`) in `--git-path info/exclude`, rules read from the kit's agent `gitignore` template through `layout.json`'s `scaffold_ignore_files`, never hard-coded. Then, for a Cinna remote only, the `neverTravelPaths` entries, anchored and with every letter a bracket of both cases (`/[cC][rR]…[sS]/`, `/.[cC][lL]…[nN]`) by `icaseIgnoreRule`. The bracket form matches another case even where the clone's `core.ignorecase` is false (a Linux clone; macOS and Windows set it true at init), where a plain rule would leave `.Claude/Settings.local.json` a new file for `add -A` to record
- `neverTravelPaths(workshopRoot)`: `getLayout(workshopRoot).never_travels`, which `parseLayout` reads from `shared_remote.never_travels.paths`. When that is absent or empty, `NEVER_TRAVELS_FALLBACK` (`credentials/`, `app-data/`) applies. Each entry keeps its shape — a trailing `/` a folder, else a file (contract 1.9.0) — after core's normalisation (no leading `./` or `/`), and an entry already listed in another case is dropped. `NEVER_TRAVELS_FILES_FALLBACK` (`.claude/settings.local.json`) is appended unless the list already has it in some case, so it applies whatever the workshop's contract version
- `dropNeverTravelsFromUnsent`: `fetch origin` (`fetch_failed` on failure), then `rewriteUnsent`. When the team ref is not an ancestor of `HEAD`, it then runs `pullRebaseClean`, whose `dirty` / `diverged_conflict` is the answer
- `rewriteUnsent(gitPath, dir, never)`: `rev-list --full-history <HEAD> --not <team ref> -- <never-travel paths>` (`icasePathspec`: `:(icase)credentials`, `:(icase)app-data`, `:(icase).claude/settings.local.json`; `:(icase)` is pathspec magic since git 1.8.3, a file entry still matching only that path), or all of `HEAD` when there is no team ref. If nothing touches those paths, it does nothing. A detached `HEAD` is refused `failed` with a sentence. Otherwise it walks `rev-list --reverse --topo-order --parents` over the same range. For each commit, it rebuilds the tree in a scratch `GIT_INDEX_FILE` under the git dir (`read-tree`, `rm -r --cached`, `write-tree`). Then `commit-tree` uses the original message (raw from `cat-file`), author, committer and dates, and the mapped parents. Commits whose tree and parents did not change are kept as they are. The branch moves by `update-ref <branch> <new> <old>` (compare-and-swap). The working tree and the real index are never touched
- `restoreLocalOnlyFolders(dir, workshopRoot)`: copies each never-travelling folder and file from the agent template (`cpSync`, `force:false`, parent made first). It then gives any dotless template ignore file under them its dot, as `scaffold_ignore_files` maps it
- `setCinnaServer(dir, origin)`: `git config cinna.server <origin>`, returning false when git refused
- `preflightShare(dir, workshopRoot, neverTravel)` — `git_missing`, else for a folder that is already its own repository `guardSecrets(…, untrack: false)` (`secrets_tracked`). Read-only apart from the exclude block; a folder that is not a repository yet tracks nothing and is guarded again when recorded
- `diffForSummary(dir)` — `diff <merge-base>` with every tracked secret (`trackedSecrets`) excluded by `:(exclude,literal)` pathspec, plus untracked file *names*; capped
- `initWithRemote` — `init -b main` unless already its own repo, `writeMissingIgnoreFiles`, `guardSecrets` (check only) **before** `remote add` (a refused folder is not left looking shared), `commitAll` "Shared with the team", for a Cinna remote `dropNeverTravelsFromUnsent`, `push`
- `clone` — into `.<slug>.clone-<hex>` beside the target, `--single-branch`; `not_an_agent` without a manifest; `ensureAgentExcludes` (never-travel folders only for a Cinna remote); rename into place; `excludeFromEnclosingRepo`
- `readHistory(dir, limit = HISTORY_LIMIT)` — `[]` unless own repo with a `HEAD`; `log -n 30 --format=%H%x1f%s%x1f%an%x1f%aI%x1e HEAD`, split on the record separator; `unsent` for each sha in `rev-list refs/remotes/origin/main..HEAD`, none when there is no `origin/main`. Reads only the local refs: no fetch
- `unsetCinnaServer(dir)` — `config --unset-all cinna.server`; a key that was not set (exit 5) counts as unset, checked by `config --get`
- `excludeFromEnclosingRepo(dir)` — appends `/<rel>/` to the enclosing repository's common-dir `info/exclude`, once

## State Management

- Query keys (`useSharing.ts`) are prefixed `['sharing', …]` and keyed by the active profile, because `other_account` and access read differently under another account
- `sharingPeopleKey(profile, agentId)` and `sharingHistoryKey(profile, agentId)` sit under the same `['sharing', …]` prefix, so `useSharingWatch` refreshes them with everything else. `useSharePeople` and `useShareHistory` have a 30-second `staleTime` and no interval
- `useSharingWatch` invalidates every sharing query and the Inbox on `sharing:changed`. It also listens to `local-agent:changed`, since main publishes `sharing:changed` only when an action or a library read settles and a folder edit is what moves `changedFiles`: a named agent re-reads its `sharingStatusKey` (any profile), a root push (`agentId: null`) every status plus the statuses list. The reads it triggers never fetch: the active status queries about to refetch are put in `quietReads`, which `useShareStatus`'s `queryFn` consumes before consulting the fetch clock. It lives here rather than in `useLocalAgentWatch` because this module owns the clock and the keys, and `useSharing` already imports `useLocalAgents`
- `useShareStatus` for an `external` remote passes `fetch: true` at most once a minute per agent, decided from a module-level clock (`lastExternalFetch`) rather than from "this is a refetch" — a fetch publishes `sharing:changed`, which invalidates the status, which would otherwise fetch again
- Mutation settle writes the returned status into the caches and invalidates the list, the library, every agent's People and History, and — after an action that rewrote a folder — the agents list
- `useSetSharePeople` writes the answered list straight into that agent's People key before invalidating it, so the next edit builds on the server's list and a select does not snap back while the refetch runs
- `useUnshare` on success sets the agent's status key to `null` and drops it from every cached statuses list at once; that removal is what takes the badge and the Sharing tab away (the page then falls back to Overview)

## Configuration

- `REFRESH_INTERVAL_MS` (libraryService) — five minutes
- Git timeouts are the root-update half's: local reads and the long network timeout per network child
- `HISTORY_LIMIT` (gitService) — 30 versions; the people search asks for `limit=10` and waits `SEARCH_DEBOUNCE_MS` (250, `ShareDialogs.tsx`) after typing
- `MAX_SUMMARY_DIFF_CHARS` 16 000 (what the summary reads), `MAX_SUMMARY_CHARS` 600 (what the field keeps), `MAX_DETAIL_CHARS` 300 (server words carried back)

## Security

- **The token** — minted per git child, environment only, header scoped to the remote's origin, redirects off, only for a remote whose instance is the active profile's (`other_account` reaches no network). `scrubCredentials` on every stderr that is logged or returned; `redactRemoteUrl` on `AgentRemote.url`
- **Origins** — `src/main/services/libraryTrust.ts` keeps, in `<userData>/team-library-trust.json` (main-only; the settings store is renderer-writable), the git origins each instance named in a listing (`libraryService.refresh` learns every `clone_url`) or a create answer, and the pending entry per instance and slug. `parseRemote` calls a remote `cinna` only when its git origin is an instance's own or trusted by it (`trusts` / `serversFor`); `.git/config` `cinna.server` (`gitService.setCinnaServer`) only picks among those, then the active profile's host. `authFor` re-checks `trusts` before minting. `acceptableGitOrigin`: https, or http only from an http instance or to loopback
- **Secrets** — kit ignore rules forced through `.git/info/exclude`; `secrets_tracked` before any record, and for Share with the team before the library entry exists; missing kit ignore files written on first share; tracked secrets left out of the text the AI summary reads
- **Who can get a new entry** — core applies the create's `grants`, so a new entry is readable only by the sharer and the people named from the start. `createAndSend` still sends nothing until the grants `PUT` succeeds, which on a core that predates grants-on-create (and gives everyone `read`) is the only restriction (see [the business rule](team_sharing.md#a-new-agent-reaches-only-the-people-chosen-never-everyone))
- **Identity** — never the machine's login or host name in a recorded version
- **Plaintext on the server, by design** — an agent in the Team library is an ordinary git repository on the Cinna server, readable by the server and by everyone the library grants. Unlike [data sync](../../sync/data_sync/data_sync.md), nothing here is end-to-end encrypted; the protection is what is kept out of the repository
- **Paths** — every folder is resolved in main from an agent id or a library repo id; Get's target is `Local/<slug>` under the agents home with the slug checked against `SLUG_PATTERN`
