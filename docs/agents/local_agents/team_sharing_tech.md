### Main process

- **Never-travelling folders** (in `gitService.ts`) — `neverTravelPaths()` (the layout's `never_travels`, parsed by `parseLayout` from `shared_remote.never_travels.paths`; `NEVER_TRAVELS_FALLBACK` for a workshop `.cinna-kit/` older than 1.8.0, `NEVER_TRAVELS_FILES_FALLBACK` for one older than 1.9.0), applied only when the remote is a Cinna library (`isCinna(auth)`). ## Database Schema

None. Whether an agent is shared comes from each folder's `origin` and from `libraryService`'s in-memory cache, and a restart lists the library again. Outside the database:

- `<userData>/team-library-trust.json` (`libraryTrust`): `{gitOrigins: {<instance origin>: [<git origin>…]}}`. A `pending` map an older build wrote is ignored on load and dropped at the next save. The instance's own origin is never written to it. It is written atomically (temp file, fsync, rename). A failed write is logged, and the list still holds in memory for that run. A host with no `userData` keeps it **in memory only**, never in a shared fallback such as the temp directory, where any local user could plant a trust list
- `cinna.server` in each shared folder's `.git/config`: the instance's API origin, written after Get and after Share with the team once `.git` exists
- `<userData>/catalog-device.json` (`catalogLocalInstalls`): `{deviceId}`, a `randomUUID()` minted on first use and written atomically (temp file, fsync, rename); an unreadable file, or an id that is empty or over 128 characters, is replaced. A failed write keeps the id in memory for the run. A host with no `userData` keeps it in memory only
- `adoption` in a shared folder's `app-data/desktop.json`: `{startedAt, headBefore, teamHead, base, chatId, mode: 'rebase'}` while a session is in progress, written by `sharingService.beginAdoption` **before** `pullRebaseClean` runs and cleared by `finishAdoption`, `discardAdoption`, or `beginAdoption` itself when the combine did not land or when it threw with HEAD still at `headBefore` (`clearAdoptionUnlessMoved`; once HEAD moved the record stays for Discard); `teamChangesDeclinedHead`: the team head Not now was answered for. `app-data/` is in the exclude block and never travels, so no git verb in the folder touches either
- `shared_remote` in each shared folder's `app-data/desktop.json`: `{kind, repo_id, clone_url, bundle_id?}`, written and cleared by `writeLocalLink` and never read for a decision; `bundle_id` (contract 1.10.0) is the catalog id, written from the entry by `linkFor` on Get and Share with the team, and read only by `recordedBundleId` to show it. `coerceSharedRemote` keeps one another host wrote when any other field of the file is patched. `writeLocalLink` replaces the whole link, so the clears (Remove sharing, the kept copy, a restarting share) drop it

## IPC Channels

Every handler calls `userActivation.requireActivated()`, runs in the settings scope (folder agents are machine-local) and reads the active **profile** itself for the token and the library. Only ids cross; no path ever arrives from the renderer. Each resolves a `SharingOutcome<T>`: refusals travel inside `value` as `ShareRefusal` codes, and `success: false` carries only what no surface can show as a state — `reauth_required` (which `_wrap` turns into the app-wide prompt) and a coded `DomainError` such as `not_found`. Anything else throws. The `catalog.ipc.ts` convention.

| Channel | Signature |
|---|---|
| `sharing:statuses` | `() → AgentShareStatus[]` — every shared agent, no network |
| `sharing:status` | `({agentId, fetch?}) → AgentShareStatus \| null` — null when not shared |
| `sharing:draft-message` | `({agentId}) → string` — AI summary, `''` on any failure |
| `sharing:share-changes` | `({agentId, message}) → AgentShareResult` |
| `sharing:update` | `({agentId}) → AgentShareResult` |
| `sharing:use-team-version` | `({agentId}) → AgentShareResult` — `agentId` in the result is the kept copy; on success the handler calls `acpProcessPool.retire(agentId)` |
| `sharing:begin-adoption` | `({agentId}) → AdoptionBeginResult` — `brief` is the session's first message, null unless `done`; `diverged_conflict` with the folder as it was (plus the recorded loose edits); `autoAttached` / `setupNeeded` as after an Update |
| `sharing:adoption-chat` | `({agentId, chatId}) → AgentShareResult` — records the session's chat; `adoption_blocked` without a session or for a chat the active profile does not see |
| `sharing:finish-adoption` | `({agentId}) → AdoptionFinishResult` — `summary` is the agent's text after *Summary of what I did*, null unless `done`; a refused check is `adoption_blocked` with the sentence as `detail` and the record kept; nothing is recorded |
| `sharing:discard-adoption` | `({agentId}) → AgentShareResult` — `adoption_blocked` without a session or when the folder could not be put back (a fixed sentence, never git's output) |
| `sharing:dismiss-team-changes` | `({agentId}) → AgentShareResult` — Not now; `failed` while no team version is known to remember |
| `sharing:share-with-team-draft` | `({agentId}) → ShareWithTeamDraft` |
| `sharing:share-with-team` | `({agentId, name, people, everyone}) → AgentShareResult` — `people: {userId, access}[]`; `everyone === true` creates it `public` (anything else `users`); the description is the manifest's, never taken from the renderer |
| `sharing:people` | `({agentId}) → AgentPeopleDto \| null` — null when the active profile cannot speak for the entry (not shared, `external`, another account's, not in the listing, or a `404`); an `everyone` row when the item is `public` and listed |
| `sharing:set-people` | `({agentId, people: LibraryGrantInput[]}) → SetPeopleResult` — the whole list, `everyone` included; `people` in the answer is the server's, also on a refused visibility |
| `sharing:item-people` | `({itemUuid}) → AgentPeopleDto \| null` — a catalog **skill**'s People by its package uuid; null when the active profile's listing does not carry a skill with that uuid (an agent's uuid included) |
| `sharing:set-item-people` | `({itemUuid, people}) → SetPeopleResult` — as `set-people`; `agentId` null in the answer; a skill the listing does not carry is `failed` with "This skill isn’t in the catalog any more." |
| `sharing:search-people` | `({query}) → PersonSearchResult[]` |
| `sharing:history` | `({agentId}) → AgentVersionDto[]` — `[]` when not shared |
| `sharing:unshare` | `({agentId, deleteFromLibrary}) → AgentShareResult` — `deleteFromLibrary` is taken only as a literal `true` |
| `sharing:library` | `({refresh?}) → LibraryListingDto \| null` — null for a non-Cinna profile |
| `sharing:get` | `({repoId}) → AgentShareResult` — `agentId` is the new row |
| `sharing:changed` | main → renderer event, no payload |

`AgentShareResult` carries the status after the attempt, so the surface needs no refetch. On a successful Use the team's version its `detail` names the per-machine files that could not be copied. After a successful Get, Update that moved the folder, or Use the team's version, `autoAttached` lists `{slot, credentialName}` for each credential main attached and `setupNeeded` says Finish setup should open: after a Get, any required slot unsatisfied; after an Update or Use the team's version, a required slot unsatisfied that was not before the verb. Every other result carries `[]` and `false`.

## Services & Key Methods

### `libraryService`

- `refresh(userId)` — `cinnaFetch(CATALOG_ITEMS_PATH)`, rows from `data`; each through `toCatalogItem` into `CachedListing.items` (every kind, as sent — what the Catalog dialog reads through `items()`), then the desktop agents through `toLibraryEntry` into `agents`. `toLibraryEntry` maps `display_name` (else `name`, else the slug), `desktop.head_sha` (`''` before the first share), `desktop.engine`, `desktop.manifest_id`, `access` (anything unknown reads `use`), `visibility` (unknown reads `private`), `is_listed` (absent reads listed), and `latest` → `{number: revision_number, label: version (trimmed, empty → null), publishedAt, publishedBy: published_by.display_name, releaseNotes}` or null. `404`/`403` → empty listing with `available: false`, logged once per host in `missingRoutesLogged`. `statusOf`'s `removed` and `removedFromLibrary` both require `available`, so a stand-in listing never reads as an entry deleted. other errors thrown. Every agent's `clone_url` goes to `libraryTrust.learn(host, …)`. Publishes `sharing:changed` only when `sharingSignature()` (host + sorted `uuid:repoId:headSha:access:visibility:isListed:latest.number`) moved; otherwise `catalog:items-changed` when `itemsSignature()` moved — host, `available`, and per item of every kind `kind:uuid:display_name:access:latest.revision_number:latest.version` and the caller's own installs, sorted, but not `install_count`, since someone else's install is no reason to re-read. At most one of the two per listing: the renderer re-reads the dialog's items on either. `sharingSignature` stays narrow because every sharing read, each shared agent's git status among them, re-reads on it. Overlapping refreshes are ordered per profile by a sequence taken at the start (`started`) and the one the cache holds (`applied`): an answer from a refresh older than the cached one is dropped (no cache write, no publish) and its caller gets the cached, newer listing — never one that started before it did. Not coalescing, which could hand a caller an answer from a request that started before it asked
- `onListingChanged(listener)` — called with `(userId, listing)` after a refresh whose listing moved by either signature (never on a poll that found nothing new, never for a dropped older answer); returns the unsubscribe. A throwing listener is logged and does not stop the others. Its one subscriber is `cloudUpdateFollow` ([Bundle Updates](../bundles_catalog/bundle_updates_tech.md#inbox-card-cloudupdateitems))
- `items(userId, refresh)` — the whole listing, every kind, as `CatalogItemsListing` (`fetchedAt` as ISO); the cache unless `refresh` or there is none; null for a profile that is not a Cinna one. Behind `catalog:items`
- `itemDetail(userId, uuid)` — `GET /api/v1/catalog/items/{uuid}` through `toCatalogItem`, with `revisions` newest first (rows without a `revision_number` dropped). Not cached in main; the renderer keeps it while the dialog is open. `DomainError` `not_a_cinna_profile`, `invalid_id` (empty uuid), `invalid_response`; anything `cinnaFetch` throws. Behind `catalog:item`
- `refreshQuietly(userId)` — for timers; on `reauth_required` it stops the poll (activation after the re-auth restarts it). A `generation` counter drops the result of a refresh that outlived a `stop()`
- `cached(userId)` — the listing only while its host is still the profile's server; a profile re-pointed elsewhere does not keep the old host's agents
- `knownHosts()` — origins of **every** Cinna profile on the machine; with `libraryTrust` (git origins an instance named) and the folder's `cinna.server`, what makes a remote `cinna` rather than `external`. Whether its token may be used is `authFor`'s separate question

### `sharingService`

- `locateKit` / `locateShared` — through `localAgentService.locate`; a kit agent whose real parent is the root's `Local/`, then `gitService.readShareRemote` for own-repo + `origin`
- `authFor(shared)`: `external` means the user's own git. A `cinna` remote on the active profile's host gives `{kind:'cinna', origin: <git origin of originUrl>, token: () => getCinnaAccessToken(profile)}`, but only after `libraryTrust.trusts(host, gitOrigin)` passes a second time. Otherwise it falls back to `external`. A `cinna` remote on another host gives `'other_account'`, and the caller reads counts with no network
- `statusOf` — first `recoverLocalOnlyFiles`: when `hasLeftoverLocalOnlyFiles`, takes the turn lock (skipped while anything holds it — never mid-action) and `restoreLeftoverLocalOnlyFiles`. `shareChanges`, `useTeamVersion` and `unshare` call `restoreLeftoverLocalOnlyFiles` right after taking the lock; `update` gets it from `pullRebaseClean`. Run at the end of `update`, `useTeamVersion` (for the team's version, which keeps `agentId`) and `get`, each after the rescan so the slots are the new files'
- `useTeamVersion` — mints the token before anything moves; `freeMineDir`; rename; `gitService.clone`; `carryMachineFiles` (ignored paths minus `NOT_CARRIED`, `cpSync` with `force:false`; answers the paths it could not copy, which `missedDetail` puts — up to three, then "and N more" — in the result's `detail`); for a Cinna remote, `settleLocalOnlyFiles` with `keepLocalOnlyFiles(mineDir)` (a never-travel file the old folder still tracked was not ignored, so not carried; the team's tracked copy is overwritten); fresh id, `slug: basename(mineDir)` (else `manifest.slug.folder_mismatch` and two agents on one slug) and "(my copy)" via `writeManifest` while the copy still has `origin`; `freeMineDir` trims the base so `<base>-mine[-n]` stays within 63 characters; then `writeLocalLink(copy, null)`, `removeOrigin` and `excludeFromEnclosingRepo` on the copy. Any throw between rename and new id → `putBack` (a landed clone is renamed to `.<slug>.discard-<id>` before deletion — the scanner skips dot-folders — so a partial delete never leaves the original id at the path and never blocks the rename-back) and rethrow `CinnaReauthRequired`, else `failed`
- `shareWithTeam`: refuses without a Cinna profile, outside `Local/`, and on `git_missing`; refuses `failed` ("…has no id, so it can't be shared") when `readManifest` gives no `id`. It refuses `remote_exists` unless `removedFromLibrary` holds, meaning `origin` is a `cinna` remote of the active host that a fresh `libraryService.refresh` with `available: true` does not list. For a restart, `removeOrigin` + `writeLocalLink(dir, null)` only now, after the entry exists; `gitService.initWithRemote` with the header scoped to the git origin; `recordServer` and `writeLocalLink(linkFor(entry))` whenever `.git` exists, sent or not. No install is reported
- `libraryTarget(userId, agentId, fresh = false)` — a `cinna` remote with a repo id whose `authFor` is the active profile's, else null; with it, `entry` (the listed agent with that repo id, from the cache unless `fresh`, refreshed once on a miss) and the `listing` it was looked up in. `entry` is null when the listing does not carry the repo; every catalog route needs its `uuid`
- `people(userId, agentId)` — null without a `libraryTarget` entry; `GET /api/v1/catalog/items/{uuid}/grants` through `fromCoreGrants`, which reads a bare array of `{principal, access, display_name}` (also one under `grants` / `data`), a principal object with `user_id` / `role`, the name from `display_name`, `full_name` or `email` on the row or the principal, and drops a row it cannot place (an unknown access reads `use`); then `withEveryone(list, entry.visibility, entry.isListed)` appends `{principal: {kind: 'everyone'}, access: 'use'}` only for a `public`, listed item. `403` → `{visible: false, people: [], selfUserId: null}`; `404` → null; anything else throws. `selfUserId` from `selfIn`: `getStoredCinnaSubject(profile)` (the stored token's `sub`, no network), kept only when it is a user in the list
- `readItemPeople(profile, item)` / `writeItemPeople(profile, item, people, agentId, reread)` — the read and the write below for any catalog item (`uuid`, `visibility`, `isListed`); `people` / `setPeople` resolve the agent's entry and call them, `itemPeople(itemUuid)` / `setItemPeople(itemUuid, people)` resolve a skill by `skillTarget(uuid, fresh)` — the cached listing's `kind: 'skill'` row with that uuid (compared without case), else a fresh listing
- `setPeople(userId, agentId, people)` — `libraryTarget(…, fresh: true)`: none → `not_shared`, no entry → `not_in_library`. `parseGrantInputs` rejects the whole list on one malformed row (`failed`); `PUT …/grants` with `toCoreGrants`, which drops `everyone`; a refusal returns before any visibility write. Then `visibilityFor(list)` (`public` with an `everyone` row, else `users`); when that differs from the entry's, `PATCH /api/v1/catalog/items/{uuid} {visibility}` — except for an unlisted `public` entry asked for `users` (`keepsHiddenPublic`), left as is. `refreshListing()`. The answer's `people` is `withEveryone(fromCoreGrants(PUT body), visibility, isListed)`, or a fresh `people()` when the body was empty; then `sharing:changed`. A refused `PATCH` returns its refusal with that list. No turn lock: it writes nothing on disk
- `libraryWrite(profile, path, method, body?, goneIsDone)` — the one writer for grants, visibility (`PATCH`) and delete. A 2xx with no JSON (`invalid_response`) is a write that happened; `404` with `goneIsDone` is success; `403` is `no_access` rather than `cinnaFetch`'s `reauth_required` (a role, not a dead session); a real `reauth_required` still throws for the prompt; anything else is `failed` with the server's `detail`
- `searchPeople(query)` — under two trimmed characters, or a profile with no host, `[]` without a request; `GET /api/v1/users/search?q=…&limit=10`, rows from `data` (`id`, `email`, `full_name`, the name falling back to the email); `403` / `404` → `[]`
- `history(userId, agentId)` — `locateShared` then `gitService.readHistory`; `[]` when not shared
- `unshare(userId, agentId, deleteFromLibrary)` — `not_shared` without `locateShared`; turn lock (`turn_in_progress`); `kept = listedEntry(shared)` before anything moves; with `deleteFromLibrary`, `libraryTarget(…, fresh: true)` (else `other_account`): with an entry, `DELETE /api/v1/catalog/items/{uuid}` through `libraryWrite(…, goneIsDone: true)`, a refusal (core's 409 "N people use this…", a `403`) returning before anything local; with none, `fetch_failed` unless the listing was `available` (then it counts as already deleted). Then `gitService.removeOrigin` (`failed` when git refused), `writeLocalLink(dir, null)`, `unsetCinnaServer` (a failure only logged). After the lock: when nothing was deleted and `kept` exists, `void catalogLocalInstalls.reportRemoved(profile, kept)`; `refreshListing()` and `settle` (rescan + `sharing:changed`). It never calls `refuseUnsharedChanges`
- `library(userId, refresh)` — the cached or refreshed listing joined to this machine: `localCopies` maps by repo id (from `origin`) and by manifest id; `updateAvailable` from `isBehindLibrary`
- `get(userId, repoId)` — listing (refreshed once on a miss) → `not_in_library`; `SLUG_PATTERN`; `libraryTrust.learn` the `clone_url` (refused when not acceptable); `exists` on slug or manifest id (`sameManifestId`, both checks); clone into the **agents home** (`agentsHomeService.requireRoot`); `recordServer`; `restoreLocalOnlyFolders`, `settleLocalOnlyFiles(target, new Map())` (a never-travel file the team's version carries becomes the template's) and `writeLocalLink` (a failure there is logged, not a refusal); re-check the manifest id that arrived and remove the clone on a clash; rescan; `credentialSetup` with no `before`; `void catalogLocalInstalls.reportInstalled(profile, entry, status.headSha)`
- `beginAdoption(userId, agentId)` — `not_shared`, `other_account`, `adoption_in_progress`, then the turn lock (`turn_in_progress`); `missingSlots` before git; `gitService.beginAdoption(dir, auth, identity, root, onPoints)`, whose `onPoints` callback writes the record (`writeAdoption`, throwing `write_failed` as every desktop-state write does — no record, no session) before the combine. Not `done` with a record written → `clearAdoption`; a throw after the record → `clearAdoptionUnlessMoved`, then rethrown; `done` → `adoptionBriefFor(shared, points)` (`readVersionsBetween` and `diffBetween` for `base..teamHead` and `base..headBefore`, through `buildAdoptionBrief`). After the lock, as `update`: `refreshListing`, `settle`, `credentialSetup(…, missingBefore)`, `catalogSkillService.ensurePinnedInBackground`; no install is reported, since nothing was sent
- `setAdoptionChat(userId, agentId, chatId)` — `adoption_blocked` (`NO_SESSION`) without a record, or (`NO_SUCH_CHAT`, "That chat could not be found.") when `sessionChatVisible(chatId)` fails; else patches `chatId` into the record (an empty string reads as null) and publishes `sharing:changed`. `sessionChatVisible` is `visibleChat(getProfileScopeUserId(), id)` that is not soft-deleted — the scope `chat:get` answers from; `buildStatus` applies it too, so `adoption.chatId` reads null for a gone chat while the record keeps the id
- `finishAdoption(userId, agentId)` — `adoption_blocked` (`NO_SESSION`) without a record; turn lock; `gitService.checkAdoptionFinish(dir, record.teamHead)`; when it passes, `liftAdoptionSummary(messageRepo.lastByRole(record.chatId, 'assistant')?.content)` (null without a recorded chat, or one `sessionChatVisible` rejects), then `writeAdoption(dir, null)`. **No `commitAll`**: the session's edits stay loose, and the next `shareChanges` records them under the note the dialog sends. `settle` on success; `summary` in the answer only when `done`
- `discardAdoption(userId, agentId)` — `adoption_blocked` (`NO_SESSION`) without a record; turn lock; `gitService.discardAdoption(dir, record.headBefore, root)`; the record cleared only when that was `done`; `settle` either way
- `dismissTeamChanges(userId, agentId)` — `statusOf` without a fetch; `failed` while `remoteHeadSha` is null; else patches `teamChangesDeclinedHead` with it. No lock: nothing in the working tree changes
- `teamChanges(userId)` — the Inbox's desktop **Update available** items (`target: 'desktop_agent'`): per shared Cinna agent, `teamChangeOf` (`readShareRemote` + `isBehindLibrary`; `version` / `versionLabel` from the entry's `latest.number` / `label`, `changedBy` and `changedAt` from its `latest.publishedBy` / `publishedAt`). A worktree's `.git` file is not memoised

### `gitService` share verbs

- `run(..., extraEnv)` — the one runner both halves use; `extraEnv` is merged last and carries only `authEnv`
- `authEnv(auth)` — `GIT_CONFIG_COUNT=2`, `http.<origin>/.extraHeader = Authorization: Bearer <token>`, `http.followRedirects = false`. Called per network child (`runNet`), so each gets a freshly minted token
- `readShareStatus(dir, auth, fetch, libraryHeadSha?, cinnaRemote = isCinna(auth))` — `teamRef` is `origin/main`, else the upstream; ahead/behind by `rev-list --left-right --count`; with a library head not in history, `behind` is the count when the commit is present, else `-1`. `changedPaths` = untracked-not-ignored + `diff --name-only <merge-base>`, minus, when `cinnaRemote`, every never-travel path (`travelsNot`) — so a team version that still tracks `.claude/settings.local.json` never counts this machine's differing copy. `statusOf` reads with no auth and passes `remote.kind === 'cinna'` itself
- `shareStateOf(counts)` — `diverged` / `behind` / `unshared` / `up_to_date`; `other_account` and `removed` are main's
- `pullRebaseClean(dir, auth, identity, workshopRoot)` — for a Cinna remote, `restoreLeftoverLocalOnlyFiles` first, `ensureAgentExcludes` (so a put-back file is ignored), `keepLocalOnlyFiles` + `saveLocalOnlyBackup`, then `checkout HEAD -- <never-travel files HEAD tracks>` so an edited tracked copy is not `dirty`; after `bringInTeamChanges`, in `finally`: not done → a checked-out file that was absent before is removed; `putBackLocalOnlyFiles` with overwrite (template and `carried` = `trackedLocalOnlyFiles` only when done), and the backup dropped when every write succeeded. `bringInTeamChanges`: fetch; nothing behind → not done, no refusal; tracked edits or an untracked file on an incoming path → `dirty`; no local versions → `merge --ff-only`; local versions and `options.combine` unset → `dirty` (the combine is a decision: `pullRebaseClean(dir, auth, identity, root, {combine?: boolean})`; `push`'s retry, `sendCombined`'s retry, `dropNeverTravelsFromUnsent` and `beginAdoption` pass `combine: true`, Update and the Inbox card do not, so the Inbox shows the `dirty` sentence in that state); else, for a Cinna remote, `rewriteUnsent` first, then `rebase --no-autostash`, aborted on failure → `diverged_conflict`
- `teamTouchedMyFiles(gitPath, dir, auth, fetch = true)` — the send gate: with `fetch`, `fetch origin` first (`fetch_failed`); then `merge-base HEAD <team ref>`, `diff --name-only <base> <team ref>` against `diff --name-only <base> HEAD`; any path in both → `team_changed_again`; null (no gate) when there is no team ref, the folder already contains it, or the files are disjoint. Measured from the common point rather than from the last fetch, because a status read may already have fetched the team's versions and the gate must still see them. Called by `dropNeverTravelsFromUnsent` (after its own fetch, `fetch: false`) before the `pullRebaseClean` that precedes a send, and by `push` before its `non_ff` retry. `sendCombined`'s one Update is gated the same way (`fetch: false`, after its own fetch), so no send path combines over an overlap
- `push` — `push -u origin HEAD:main`; `classifyPush` → `non_ff` (`teamTouchedMyFiles`, then one `pullRebaseClean`, `rewriteUnsent` again for a Cinna remote, one retry), `no_access`, `push_rejected` (server's `remote:` lines as `detail`), `fetch_failed`. For a Cinna remote whose refusal is the server's policy (`refusedByPolicy`: `push_rejected` with `(pre-receive hook declined)` and neither core's `MSG_UNAVAILABLE` — `POLICY_UNAVAILABLE`, *can't check this change right now* — nor `MSG_MANIFEST_ID_CHANGED` — `IDENTITY_CHANGED`, *identity changed; share it as a new agent*; `failed to lock` and other `[remote rejected]` reasons excluded), `sendCombined`
- `sendCombined` — refused unchanged on a detached `HEAD` or a failed fetch; when the team ref is not an ancestor of `HEAD`, `teamTouchedMyFiles` (`fetch: false`) and then one `pullRebaseClean({combine: true})` + `rewriteUnsent` first; the same gate guards its `non_ff` round. `combineUnsent`: `rev-list --no-merges <HEAD> --not <team ref>` (null, so the original refusal stands, with fewer than two); notes by `log -1 --format=%B`, newest first, de-duplicated; `commit-tree <HEAD>^{tree} -p <team ref>` with `commitFlags`; pinned at `refs/cinna/combined-<hex>` (`update-ref <ref> <sha> ''`). `push origin <scratch>:refs/heads/main`; on success `update-ref <branch> <sha> <old HEAD>` (compare-and-swap; on a miss, `replayOntoCombined`: if the branch still descends from the old HEAD, `rebase --onto <combined> <old HEAD>` — the combined tree is the old HEAD's, so only the versions recorded since replay — aborted and logged when it stops) and `branch --set-upstream-to=origin/main`; `non_ff` → one more round, at most one Update (gated); anything else is the answer. The scratch ref is deleted in `finally`
- `commitAll(dir, message, identity, workshopRoot, neverTravel)` — `guardSecrets(…, neverTravel, untrack: true)`, `add -A -- .`, `nothing_to_share` when nothing is staged, commit with `commitFlags` (`commit.gpgsign=false`; `user.name`/`user.email` only where git has none)
- `guardSecrets(gitPath, dir, workshopRoot, neverTravel, untrack)` — `ensureAgentExcludes`; with `neverTravel && untrack`, `untrackNeverTravels` (`rm -r --cached --ignore-unmatch` over `neverTravelPaths`), the only place anything is untracked; then `trackedSecrets` (`ls-files -z` against `isSecretFile` and `layout.desktopOwned()`), minus, with `neverTravel`, paths under the never-travel folders; `secrets_tracked` with up to three paths
- `ensureAgentExcludes` — the marked block (`# >>> Cinna Desktop: the agent kit's ignore rules …` / `# <<< Cinna Desktop`) in `--git-path info/exclude`, rules read from the kit's agent `gitignore` template through `layout.json`'s `scaffold_ignore_files`, never hard-coded. Then, for a Cinna remote only, the `neverTravelPaths` entries, anchored and with every letter a bracket of both cases (`/[cC][rR]…[sS]/`, `/.[cC][lL]…[nN]`) by `icaseIgnoreRule`. The bracket form matches another case even where the clone's `core.ignorecase` is false (a Linux clone; macOS and Windows set it true at init), where a plain rule would leave `.Claude/Settings.local.json` a new file for `add -A` to record
- `neverTravelPaths(workshopRoot)`: `getLayout(workshopRoot).never_travels`, which `parseLayout` reads from `shared_remote.never_travels.paths`. When that is absent or empty, `NEVER_TRAVELS_FALLBACK` (`credentials/`, `app-data/`) applies. Each entry keeps its shape — a trailing `/` a folder, else a file (contract 1.9.0) — after core's normalisation (no leading `./` or `/`), and an entry already listed in another case is dropped. `NEVER_TRAVELS_FILES_FALLBACK` (`.claude/settings.local.json`) is appended unless the list already has it in some case, so it applies whatever the workshop's contract version
- `dropNeverTravelsFromUnsent`: `fetch origin` (`fetch_failed` on failure), then `rewriteUnsent`. When the team ref is not an ancestor of `HEAD`, it then runs `teamTouchedMyFiles` (`team_changed_again` when the files overlap) and `pullRebaseClean`, whose `dirty` / `diverged_conflict` is the answer
- `beginAdoption(dir, auth, identity, workshopRoot, onPoints)` — `restoreLeftoverLocalOnlyFiles`; `fetch origin` (`fetch_failed`); `teamRef` (`not_shared` without one); `commitAll` under `ADOPTION_BEFORE_NOTE` ("Changes made before bringing the team’s version in"; `nothing_to_share` is fine, any other refusal is the answer); `headBefore = HEAD`, `teamHead`, `base = merge-base` (`failed` with a sentence when any is missing); `rev-list --count HEAD..<team ref>` zero → `failed` "Nothing to bring together…"; **`onPoints({headBefore, teamHead, base})`**; then `pullRebaseClean(…, {combine: true})` — `done`, or its refusal (`diverged_conflict` after its own abort, the tree as it was); not done and no refusal → `failed` "Nothing to bring together…". `headBefore` is the tip before `pullRebaseClean`'s never-travel rewrite on purpose, so Discard restores exactly what the user had
- `checkAdoptionFinish(dir, teamHead)` — in order: a `rebase-merge`, `rebase-apply` or `MERGE_HEAD` under the git dir (`rev-parse --git-path`) → `adoption_blocked` "An earlier combine in this folder is still unfinished." (before the HEAD check, since a stopped rebase detaches HEAD and the unfinished combine is the reason to give); `symbolic-ref -q HEAD` empty → `adoption_blocked` detached; `git grep -I -l -E --untracked -e '^(<<<<<<< |>>>>>>> )'` → `adoption_blocked` naming up to three files (`=======` alone is not checked: it underlines a markdown heading); `merge-base --is-ancestor <teamHead> HEAD` failing → `adoption_blocked` "…no longer includes the team’s version the session started from."; else `done`
- `discardAdoption(dir, headBefore, workshopRoot)` — `keepLocalOnlyFiles` + `saveLocalOnlyBackup`; `rebase --abort` and `merge --abort` (either may have nothing to abort); `reset --hard --quiet <headBefore>` (`failed` with the last stderr line when refused, local-only files put back); `clean -fd -q` with `-e /<path>` for every never-travel entry (ignored files are untouched without `-x`); `putBackLocalOnlyFiles` with overwrite and `trackedLocalOnlyFiles` as `carried`, then the backup dropped
- `readVersionsBetween(dir, from, to, workshopRoot)` — one `log --reverse --name-only` with `VERSIONS_FORMAT` (the record separator **opens** each record, so the file list git prints after the format closes the one before), split as `readHistory` does; `files` minus `travelsNot` paths; `[]` on any failure
- `diffBetween(dir, from, to, workshopRoot)` — `diff --no-color <from> <to> -- .` with `:(exclude,icase)` for every never-travel path and `:(exclude,literal)` for every `trackedSecrets` path, split on `diff --git` headers into `{path, diff}` and then any entry whose path is `secretShape(workshopRoot)` dropped — so a secret-shaped file a version *deleted*, tracked in neither tip, is never read out (`secretShape` is also what `trackedSecrets` filters `ls-files` by, so both match in any case) — each `scrubCredentials`-ed; no cap here, the brief caps
- `rewriteUnsent(gitPath, dir, never)`: `rev-list --full-history <HEAD> --not <team ref> -- <never-travel paths>` (`icasePathspec`: `:(icase)credentials`, `:(icase)app-data`, `:(icase).claude/settings.local.json`; `:(icase)` is pathspec magic since git 1.8.3, a file entry still matching only that path), or all of `HEAD` when there is no team ref. If nothing touches those paths, it does nothing. A detached `HEAD` is refused `failed` with a sentence. Otherwise it walks `rev-list --reverse --topo-order --parents` over the same range. For each commit, it rebuilds the tree in a scratch `GIT_INDEX_FILE` under the git dir (`read-tree`, `rm -r --cached`, `write-tree`). Then `commit-tree` uses the original message (raw from `cat-file`), author, committer and dates, and the mapped parents. Commits whose tree and parents did not change are kept as they are. The branch moves by `update-ref <branch> <new> <old>` (compare-and-swap). The working tree and the real index are never touched
- `restoreLocalOnlyFolders(dir, workshopRoot)`: copies each never-travelling folder and file from the agent template (`cpSync`, `force:false`, parent made first). It then gives any dotless template ignore file under them its dot, as `scaffold_ignore_files` maps it
- `setCinnaServer(dir, origin)`: `git config cinna.server <origin>`, returning false when git refused
- `preflightShare(dir, workshopRoot, neverTravel)` — `git_missing`, else for a folder that is already its own repository `guardSecrets(…, untrack: false)` (`secrets_tracked`). Read-only apart from the exclude block; a folder that is not a repository yet tracks nothing and is guarded again when recorded
- `diffForSummary(dir)` — `diff <merge-base>` with every tracked secret (`trackedSecrets`) excluded by `:(exclude,literal)` pathspec, plus untracked file *names*; capped
- `initWithRemote` — `init -b main` unless already its own repo, `writeMissingIgnoreFiles`, `guardSecrets` (check only) **before** `remote add` (a refused folder is not left looking shared), `commitAll` "Shared with the team", for a Cinna remote `dropNeverTravelsFromUnsent`, `push`
- `clone` — into `.<slug>.clone-<hex>` beside the target, `--single-branch`; `not_an_agent` without a manifest; `ensureAgentExcludes` (never-travel folders only for a Cinna remote); rename into place; `excludeFromEnclosingRepo`
- `readHistory(dir, limit = HISTORY_LIMIT)` — `[]` unless own repo with a `HEAD`; `log -n 30 --format=%H%x1f%s%x1f%an%x1f%aI%x1e HEAD`, split on the record separator; `unsent` for each sha in `rev-list refs/remotes/origin/main..HEAD`, none when there is no `origin/main`. Reads only the local refs: no fetch
- `unsetCinnaServer(dir)` — `config --unset-all cinna.server`; a key that was not set (exit 5) counts as unset, checked by `config --get`
- `excludeFromEnclosingRepo(dir)` — appends `/<rel>/` to the enclosing repository's common-dir `info/exclude`, once

## State Management

- Query keys (`useSharing.ts`) are prefixed `['sharing', …]` and keyed by the active profile, because `other_account` and access read differently under another account
- `sharingPeopleKey(profile, agentId)` and `sharingHistoryKey(profile, agentId)` sit under the same `['sharing', …]` prefix, so `useSharingWatch` refreshes them with everything else. `useSharePeople` and `useShareHistory` have a 30-second `staleTime` and no interval
- `useSharingWatch` invalidates every sharing query, the Inbox and — through `invalidateLocalAgentsAfterListing` — the local-agent list and every open agent page on `sharing:changed` (a skill's new version can arrive with a desktop agent's move, and access decides a Skills row's `updatable`), and brings the Catalog dialog's items up to main's cache (`readCatalogItemsFromCache`, no second listing). `catalog:items-changed` is `useCatalogItemsWatch`'s, in `useCatalog.ts`, and touches no sharing query. It also listens to `local-agent:changed`, since main publishes `sharing:changed` only when an action or a library read settles and a folder edit is what moves `changedFiles`: a named agent re-reads its `sharingStatusKey` (any profile), a root push (`agentId: null`) every status plus the statuses list. The reads it triggers never fetch: the active status queries about to refetch are put in `quietReads`, which `useShareStatus`'s `queryFn` consumes before consulting the fetch clock. It lives here rather than in `useLocalAgentWatch` because this module owns the clock and the keys, and `useSharing` already imports `useLocalAgents`
- `useShareStatus` for an `external` remote passes `fetch: true` at most once a minute per agent, decided from a module-level clock (`lastExternalFetch`) rather than from "this is a refetch" — a fetch publishes `sharing:changed`, which invalidates the status, which would otherwise fetch again
- Mutation settle (`applyResult`) writes the returned status into the caches — the per-agent entry and the matching entry of the statuses list, so a page reopened before the list refetches decides the banner from the new status and Not now holds — and invalidates the list, the library, every agent's People and History, and — after an action that rewrote a folder — the agents list. `useBeginAdoption`, `useFinishAdoption` and `useDiscardAdoption` take that rescan path when `done` (Finish moves the folder's counts, not its files, but follows the same path as every other action that rewrote history); `useDismissTeamChanges` only writes the status back, since nothing in the folder changed
- `useSetSharePeople` writes the answered list straight into that agent's People key before invalidating it, so the next edit builds on the server's list and a select does not snap back while the refetch runs
- `useUnshare` on success sets the agent's status key to `null` and drops it from every cached statuses list at once; that removal is what takes the badge and the Sharing tab away (the page then falls back to Overview)

## Configuration

- `REFRESH_INTERVAL_MS` (libraryService) — five minutes
- Git timeouts are the root-update half's: local reads and the long network timeout per network child
- `HISTORY_LIMIT` (gitService) — 30 versions; the people search asks for `limit=10` and waits `SEARCH_DEBOUNCE_MS` (250, `ShareDialogs.tsx`) after typing
- `MAX_SUMMARY_DIFF_CHARS` 16 000 (what the summary reads), `MAX_SUMMARY_CHARS` 600 (what the field keeps), `MAX_DETAIL_CHARS` 300 (server words carried back)
- `adoptionBrief.ts`: `MAX_FILE_DIFF_CHARS` 6 000 (one file's diff in the brief, cut at a line end with "… (N more lines not shown)"), `MAX_BRIEF_CHARS` 40 000 (the whole brief; diffs that do not fit become "… N more files are not shown here; read them in the folder.", the asks are never cut), its own `MAX_SUMMARY_CHARS` 1 500 (the agent's summary lifted into the Share changes field)

## Security

- **The token** — minted per git child, environment only, header scoped to the remote's origin, redirects off, only for a remote whose instance is the active profile's (`other_account` reaches no network). `scrubCredentials` on every stderr that is logged or returned; `redactRemoteUrl` on `AgentRemote.url`
- **Origins** — `src/main/services/libraryTrust.ts` keeps, in `<userData>/team-library-trust.json` (main-only; the settings store is renderer-writable), the git origins each instance named in a listing (`libraryService.refresh` learns every desktop agent's `clone_url`) or a create answer. `parseRemote` calls a remote `cinna` only when its git origin is an instance's own or trusted by it (`trusts` / `serversFor`); `.git/config` `cinna.server` (`gitService.setCinnaServer`) only picks among those, then the active profile's host. `authFor` re-checks `trusts` before minting. `acceptableGitOrigin`: https, or http only from an http instance or to loopback
- **Secrets** — kit ignore rules forced through `.git/info/exclude`; `secrets_tracked` before any record, and for Share with the team before the library entry exists; missing kit ignore files written on first share; tracked secrets left out of the text the AI summary reads, and of the brief's diffs (`diffBetween`: never-travel paths and `trackedSecrets` excluded by pathspec, the rest `scrubCredentials`-ed; `readVersionsBetween` names no never-travel path). The brief goes to the agent's own engine as an ordinary message, under the agent's ordinary permissions; it tells the agent not to touch `credentials/` or `app-data/`, and the app enforces nothing further there
- **The session record** — in `app-data/desktop.json`, which git ignores and never travels; a malformed record reads as none, so Finish and Discard are never offered on points that cannot be restored
- **Who can get a new entry** — core applies the create's `grants` and `visibility` (`users`, or `public` with Everyone ticked) in one transaction, so a new entry is readable only by the sharer and the people named (or everyone, when ticked) from the start; an adopted entry gets its grants rewritten, and its visibility set to this attempt's, before anything is sent (see [the business rule](team_sharing.md#a-new-agent-reaches-only-the-people-chosen-never-everyone-by-default))
- **The device id** — a random UUID, never derived from the machine, the person or the sync device id
- **Identity** — never the machine's login or host name in a recorded version
- **Plaintext on the server, by design** — an agent in the Team library is an ordinary git repository on the Cinna server, readable by the server and by everyone the library grants. Unlike [data sync](../../sync/data_sync/data_sync.md), nothing here is end-to-end encrypted; the protection is what is kept out of the repository
- **Paths** — every folder is resolved in main from an agent id or a library repo id; Get's target is `Local/<slug>` under the agents home with the slug checked against `SLUG_PATTERN`
