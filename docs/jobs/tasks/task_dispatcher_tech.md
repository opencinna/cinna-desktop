## Database Schema

All added idempotently by `migrateTasks` (`src/main/db/migrations/tasks.ts`). All are device-local: none is a synced collection, and neither task column is in the device-sync payload.

- **`agent_task_dispatch`** — primary key `(user_id, agent_id)`; `mode` (`manual` default), `paused_reason`, `paused_task_id`, `paused_at` (ms), `active_task_id`, `active_chat_id`, `updated_at`. **No row means Manual, not paused, nothing in flight.** `agentTaskDispatchRepo.patch` deletes a row that has returned to those defaults, so that rule keeps holding. A table of its own, not columns on `agent_overrides`, because an override row carries `enabled`, the same reason `agent_colors` is separate. No FK to `agents`. `active_*` is the dispatched run in flight, kept so that boot can find a run Cinna quit under. `agentRepo` rewrites `agent_id` on an agent id rename. `userRepo` deletes the rows with the profile.
- **`task_dispatch_gates`** — `id` (`dgate_…`), `user_id`, `task_id` (FK `ON DELETE CASCADE`), `agent_id`, `digest`, `title`, `file_path`, `body` (the prompt as it would be sent), `status` (`open` | `approved` | `skipped` | `superseded`), `created_at`, `settled_at`. Unique `(user_id, task_id, digest)`: one card per content. Index `(user_id, status)`. `taskDispatchGateRepo.open` supersedes, in one transaction, every open card of the task for another digest. `reopen` reopens a card (and refreshes `created_at`). `userRepo` deletes gates explicitly, since the cascade fires only with FK enforcement on.
- **`tasks.dispatch_note`** — `DISPATCH_NOTE_UNREPORTED` or `DISPATCH_NOTE_INTERRUPTED`, written only with a `blocked` status (`taskService.setStatus` `opts.dispatchNote`). `statusPatch` clears it on every other status.
- **`tasks.dispatch_agent_id`** — the queue that owns how the task settles. Set by `taskRepo.setDispatchAgent` in the run's `onRunAccepted`. Cleared by `release` (the dispatcher settled it, or boot recovery), by `statusPatch` for any status other than `in_progress` or `blocked`, by `taskService.takeOver` and `handOffToRemote`, and by a device-sync apply that changes `status`, `executor` or `executorDevice` (`taskMapper` in `sync/collections.ts` compares the row before and after, because that write skips `statusPatch`). `setDispatchAgent` and `setTrustedDigest` leave `updatedAt` alone, so the task list does not reorder for bookkeeping.

## IPC Channels

All require activation and resolve the profile in main. Refusals come back as data with a `code`, because a thrown `DomainError.code` does not survive the bridge.

| Channel | Request → response |
|---|---|
| `taskDispatch:list` | → `AgentDispatchState[]`, one per dispatchable agent (enabled local folder agents with a path, bare and kit) |
| `taskDispatch:get` | agent id → `AgentDispatchState`, or null for an agent that cannot work a queue |
| `taskDispatch:set-mode` | agent id, mode → `TaskDispatchUpdateResult`. A mode that fails `isTaskDispatchMode` is `invalid_input`. Manual aborts the queue's own slot waits for that agent |
| `taskDispatch:resume` | agent id → `TaskDispatchUpdateResult`. Clears the pause only |
| `taskDispatch:run-next` | agent id, task id? → `TaskDispatchRunResult`: `{ok, taskId, chatId}`, `{ok, gate}` (the card to open), or `{ok: false, code}` with `not_dispatchable`, `agent_busy`, `folder_busy`, `live_turn`, `slot`, `not_eligible`, `nothing_eligible`, `start_failed`, `invalid_input` |
| `inbox:dispatch-gate` | gate id, `approve` \| `skip` → `TaskDispatchGateResult`: `{ok, started, reason?, mode?}` or `{ok: false, code}` with `no_longer_waiting`, `already_answered`, `changed`, `unavailable`. In `task.ipc.ts` beside the other Inbox answers |
| `taskDispatch:changed` (push) | `{agentId \| null}`, sent through `publishEvent` whenever a queue's state may have changed. The renderer invalidates on it. `window.api.taskDispatch.onChanged` returns an unsubscribe |

`inbox:list`'s `InboxSnapshot` gains `dispatch: TaskDispatchInboxItem[]` (optional in the type only so older surfaces still compile; main always fills it).

## Services & Key Methods

### `taskDispatchService.ts`

Hub core: it imports no Electron. Everything it needs from the app is a `TaskDispatchDeps` seam that the tests replace: `agents`, `start`, `withSlot`, `slotFree`, `trust`, `refreshTask`, `liveAgentIds`, `publish`. `productionDeps` wires them to `localAgentService.list` (filtered by path and the profile's `agentOverrideRepo` enabled value), `taskExecutionService.start`, `withRuntimeAgent`, `runtimeAgentSlotFree`, `taskSyncService.trustLocalContent`, `taskSyncService.pullFresh`, `activeRunsByChat` plus working `taskRunnersByChat`, and `publishEvent(TASK_DISPATCH_CHANGED_CHANNEL)`.

- **State in memory.** `flights` (per profile and agent: `phase` `slot` → `starting` → `running`, `origin` `queue` | `manual`, the run once accepted, an `AbortController`), and `settlingOwned` (agents whose resumed owned turn is being settled, with a count). Folder identity is `path.resolve(agent.path)`.
- `refusal(userId, task, agentId)` — the eligibility sentence, or null. Ends with the `blocked_by` check over `task.blockedBy`. `candidates` filters `taskService.list({statuses: ['open']})` through it, sorts by `TASK_PRIORITIES` rank desc, `createdAt` asc, then id, and marks `gated` from `task.fromOutside`.
- `pass(scope, epoch)` — for each agent in `one` mode, not paused, with no flight and not `settling`, whose folder has no flight, no settling agent and no live turn (`liveTurnIn` covers every agent sharing the folder): walk the candidates, call `gateFor` on each gated one, and `launch` the first ungated one. `wake()` debounces by `WAKE_DEBOUNCE_MS` and chains passes on one promise, so two wakes never start two runs. An `epoch` bump (`stop`) voids passes already queued.
- **Wakes**: `setMode`, `resume`, any `taskRunnerBridge.taskChanged` (an `installTaskRunnerHooks(…, 'task-dispatch')` listener), `onRunClosed`, the end of a flight or an owned settle, `start` (profile ready), and the `TICK_MS` interval.
- `launch(scope, agent, task, origin)` — registers the flight synchronously (so a second wake sees the agent and folder taken), then `withSlot`. Inside the slot: abandon on quit or abort, re-check for a live turn in the folder (`LiveTurnError`), then `recheck`, which re-reads the task, applies `refusal` and, if it became `fromOutside`, opens its gate (`NoLongerEligibleError`). Then `setActive(taskId, null)`, then `deps.start(…, {continueInChat: !!task.chatId, onRunAccepted})`. `onRunAccepted` runs inside the run's acceptance, before any event: it stores `flight.run`, calls `markDispatchedRun`, and sets `dispatch_agent_id`. Then `setActive(taskId, chatId)`, awaits `completed`, and calls `settle`. `finally` clears the run mark, drops the flight, publishes and wakes. A start that never got going goes to `startFailed`, which pauses with `error` only for `origin: 'queue'`, and never for a live turn, a no-longer-eligible task or an abandoned wait.
- `settleTask(userId, agentId, taskId, outcome, afterRead)` — the report rule. Returns at once while `quitting`. For a file task it awaits `deps.refreshTask` first, then reads the row. `completed` / `needs_input` with an open input request → return (still owned). Otherwise `release`, then: `canceled` → `cancelled` if still `in_progress`, pause `stopped`; `failed` / `budget` → `error` with the message, pause `error`; not `reported` (category from `folderCategoryForStatus(parseTaskStatus(status))` is not done, failed, waiting or cancelled) → via `in_progress` if needed, then `blocked` with `DISPATCH_NOTE_UNREPORTED`, pause `unreported`. Status writes go through `taskService.setStatus` and a failure is only logged.
- `settleOwnedTurn(end)` — the registered `setDispatchOwnedTurnSettler`. It ignores a task whose `dispatchAgentId` is no longer `end.agentId`. It increments `settlingOwned` synchronously, before the turn's close wakes a pass, then runs `settleTask`, and decrements, publishes and wakes in `finally`.
- `runNext(scope, agentId, taskId?)` — `invalid_input` for a bad id; `agent_busy` (a flight or a settle for the agent); `folder_busy` (a flight or a settle in the folder); `live_turn`; the named task or the first ungated candidate, else the first gated; a gated choice → `gateFor(…, reopenSkipped: true)` → `{gate}`; `slot` when `!deps.slotFree()` (no queueing); else `launch(…, 'manual')` and wait for acceptance.
- `gateFor(userId, agentId, task, reopenSkipped)` — the card for the row's current `localFile.digest`. An existing card for that digest that is `approved` or `superseded` (the content is untrusted again) is reopened, and so is a `skipped` one when `reopenSkipped`. Otherwise `taskDispatchGateRepo.open` with `taskContinuationPrompt(task)` as the body.
- `answerGate(scope, gateId, action)` — `no_longer_waiting` / `already_answered`; a deleted task or a changed digest supersedes the card (`changed`); `skip` → settle `skipped`; `approve` → settle `approved`, `deps.trust` (on failure the card is reopened and the answer is `unavailable`), then `runNext(…, gate.taskId)`; a refusal is mapped to a `TaskDispatchGateDeferral` and the agent's `mode` is returned with it.
- `stateFor` — builds `AgentDispatchState`. `waiting` is `slot` for a flight in its slot phase; in `one` mode, not paused and with no flight, `folder_busy` (a flight or a settle in the folder) or `live_turn`; and `gate` only when every candidate is gated and `hasOpenGate` finds an open card for one at its current digest. With no open card, `next` is the top gated task with `needsApproval: true`.
- `recoverInterrupted()` — boot, from `initializeHubCore` before any profile activates. For every `agentTaskDispatchRepo.listActive()` row: `blocked` + `DISPATCH_NOTE_INTERRUPTED` when still `in_progress`, `release`, then clear `active_*` and pause `interrupted`. Then for every `taskRepo.listDispatchOwned()` task still `in_progress` with no open input request and no live turn: the same note, `release`, pause `interrupted`.
- `start(scope)` / `stop()` / `shutdown()` — `stop` bumps the epoch, clears the timers and aborts the queue's own slot waits (a Run next keeps its own). `shutdown` also sets `quitting` and aborts every slot wait. From then on nothing is settled, so each in-flight row stays for the next boot.

### Elsewhere

- `inboxService.endTurn` — after the ask bookkeeping, `isDispatchedRun(chatId, turnId)` returns without settling. A task with `dispatchAgentId` whose `chatId` is this chat is handed to `settleDispatchOwnedTurn` (`completed` / `failed` / `canceled`, with the error event's message). Both come before the job-run, handover and ordinary branches. `settleDispatchOwnedTurn` answers true even while quitting, so the ordinary branch never completes the task on the way out.
- `taskExecutionService.start` — `continueInChat` uses `ownChat`: the task's chat if it is still visible (else a new chat), refused when it is not `direct` to the same agent or is already running. It cannot be combined with `reuseChatId`, and it lifts the "already has a conversation" refusal. `onRunAccepted` is called from `onAccepted` with `ctx.turnId`.
- `taskService.taskBlockers(row)` — resolves `localFile.blockedBy` through `taskRepo.listFileTasksByKey` (live tasks with a `local_file` whose `remoteKey` is one of the ids), kept to files in the same directory. `done` is `completed` only, and a missing id is `{taskId: null, done: false}`. Exposed as `TaskDto.blockedBy` by `toTaskDto`.
- `taskSyncService.trustLocalContent(userId, taskId, digest)` — queued behind the task's pushes (`pushesInFlight`). It bumps the binding revision, calls `localHome.trust` and stores the returned binding through `markRemoteSynced`, bumps again, then `taskRepo.setTrustedDigest`. The bumps keep a pull that read the old binding from storing it back.
- `taskSyncService.pullFresh(userId, taskId)` — waits out any read already in flight for the task, then starts its own, retrying once if the revision check discards it.
- `jobService.reportRunCompletion` — when `takeAgentStatusReportInChat(run.taskId, chatId)` finds a report: `blocked` returns with the attempt still running; `completed` / `error` set the outcome (`succeeded` / `failed`, with the task's error) and skip `applyRunState`.
- `runExecutionService` calls `runClosed(chatId)` whenever a turn lets go of its chat, and the dispatcher wakes on it.

## Renderer Components

- `useTaskDispatch.ts` — `useTaskDispatchList` / `useAgentDispatch` (5 s poll, `retry: 1`, plus the push), `useDispatchControls(agentId, {onStarted})`, which owns `setMode`, `resume`, `runNext`, `pending`, `pendingMode`, and an `error` tagged with action and agent. Its owner is the surface, never a menu, so a result is not lost when a popover closes. `useOpenInboxGate` sets `revealInboxGateId` and switches to the Inbox. `useAnswerDispatchGate`. The shared words are `DISPATCH_MODE_LABELS`, `dispatchPausedParts` / `dispatchPausedText`, `dispatchStatusParts` and `dispatchGateSettledText`. `refreshAfterDispatch` invalidates `['task-dispatch']`, `['tasks']`, `['task']` and the Inbox.
- `AgentTasksTab` — one `SettingsSection` "Task queue": Run next in the section action, the **Run mode** select, one `data-queue-status` line that is filled in every state, the `data-queue-paused` line with Resume only while paused, and the error last. `useTasksTabBadge` drives `LocalAgentPage`'s absolutely placed `data-tab-paused-dot`, so the tab row never reflows.
- `TasksRunNextControl` — rendered by `TasksView` only while the filter is `agent:<id>` and that agent has a queue. A split button: the left half is Run next, or Resume in the warning tone while paused (with a `data-dispatch-paused` glyph whose name is the pause sentence); the chevron opens a `role="menu"` with the paused task, Run next while paused, and the modes as `menuitemradio`. Under `@3xl` the left half drops its word. A refusal shows in the move-error overlay slot.
- `TaskView` — `StartControls`: a Ready agent task goes through `QueueStartGate`. Open blockers show the Continue-with picker under **Waits on …** (`WaitsOn`). A `not_eligible` refusal replaces the picker's lead. With no queue (or a script router) it falls back to the plain picker. Otherwise `DispatchStartControls` shows **Start**, which calls `runNext(task.id)` and opens the chat. The Status row shows `dispatchNote` while blocked, and `DispatchPausedHere` (Resume) when a queue paused on this task. `BlockedByValue` renders `task.blockedBy`, one per line, with the missing ones marked "not found".
- `InboxDispatchCards` — `DispatchGateCard` (path from `.cinna/` on, Reveal, the body, **Approve and run** / **Skip**, the settled sentence) and `DispatchPausedCard` (the pause line, the note when it is not one of the two standard notes, **Resume**). `InboxView` merges asks and dispatch items into one row list keyed `gate:<id>` / `paused:<agent>:<at>`, with the same first-seen order and retention, and scrolls to and marks `revealInboxGateId` once. `inboxWaitingCount` adds `dispatch.length` for the badge and the view's count.

## Configuration

- Run mode is per profile and per device (`agent_task_dispatch`). There is no app setting.
- `taskRunnerConcurrency` (`app_settings`, default 2, 1–8) bounds dispatched turns together with autonomous and script runs. See [Autonomous Tasks (tech)](autonomous_tasks_tech.md#configuration).

## Security

- **Outside content never runs unapproved.** Only `answerGate` calls `trust`, and only for the digest the card showed and the file still has. A Cinna write onto untrusted content stays untrusted (see [Folder Tasks (tech)](folder_tasks_tech.md)).
- **The renderer decides nothing.** It sends an agent id, an optional task id, a mode or a gate id. Main resolves the profile, re-derives eligibility, and rechecks after every wait.
- **No digest or binding state reaches the renderer.** A gate item carries the title, the path and the body that would be sent.
- **Run marks are keyed by chat and run id**, so a user's own turn on the same task is never settled by the report rule.
