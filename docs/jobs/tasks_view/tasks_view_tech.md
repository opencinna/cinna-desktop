## Database Schema

- `tasks.custom_fields` — nullable JSON (`TaskCustomFields`), added idempotently by `migrateTasks` in `src/main/db/migrations/tasks.ts`. Null means "none" for every task written before the column; an empty set is also stored as null (`checkedCustomFields`), so "has none" has one spelling.
- `TaskSyncValues.customFields` is optional on purpose: `undefined` means the peer's payload had no key, and `taskRepo`'s sync upsert then leaves the column out of the update set. A sync insert writes `values.customFields ?? null`.

## Shared Rules (`src/shared/taskStatus.ts`)

- `TaskStatusCategory` (`backlog | ready | active | waiting | closed`), `TASK_STATUS_CATEGORIES` (lifecycle order = board columns), `TASK_STATUS_CATEGORY_LABEL`, `taskStatusCategory(status)` (null for `archived`).
- `CATEGORY_DROP_STATUS` — the status a drop on a user column writes: backlog → `new`, ready → `open`, closed → `completed`. Active and Waiting have none.
- `MANUAL_TRANSITIONS` — `new: [open, completed]`, `open: [new, completed]`. An overlay on `VALID_TRANSITIONS`, which stays a verbatim copy of cinna-core's table; `taskStatus.test.ts` asserts the manual-only pairs are absent from it.
- `isManualOnlyTransition`, `canTransitionManually(from, to, {bound})` — table, plus the overlay only when `bound` is false.
- `MANUAL_TARGET_STATUSES` (`new`, `open`, `completed`), `isManualSource(from, {flagged})` (category backlog/ready/closed, or `blocked` when `flagged`), `canMoveManually(from, to, {bound, flagged})` — the status half of the manual rule: from a user column, to a user column or `cancelled`, along `canTransitionManually`. A flagged `blocked` task reaches `cancelled` (in the table) and, unbound only, the user columns. The renderer passes `flagged` = `blocked` with a `dispatchNote` (`isDispatchFlagged` / `manualMoveOptions` in `tasksViewModel.ts`, also used by Edit task's `heldReason`); main (`taskService.setStatus`) passes it only when, besides, `taskInputRequestRepo.listOpenForTask` is empty, and still applies its runtime and live-run refusals.
- `manualTargets(from, {bound, flagged})` — the user-column statuses reachable, `from` excluded. It never lists `cancelled`, which `canMoveManually` allows; the category board and a non-file task's moves never offer it. A folder board's Cancelled-category columns are droppable, and a file task's moves to them are judged by `canMoveManually` directly (`folderMoveTargets`).

## IPC Channels

| Channel | Request → response |
|---|---|
| `task:create` | payload → `TaskDto`. `parseTaskCreatePayload` rebuilds it field by field: `title` (required string), optional `goal`, `description`, `priority` (`isTaskPriority`), `status` (`new` or `open` only), `assignee` (`TaskAssigneeInput`), `customFields` (a plain object, else refused), `parentTaskId` (a non-empty string; the task page's Add subtask). Through `taskAuthoringService.createRouted`, which checks the parent with `checkParent`, and which writes a bare agent's task into its folder ([Folder Tasks](../tasks/folder_tasks_tech.md)). Captures profile and settings scopes; marks device sync dirty |
| `task:update` | task id, payload → `TaskDto`. `parseTaskUpdatePayload`: `title`, `description` (string or null), `priority`, `router` (`TASK_ROUTERS`), `assignee`, `customFields` (object, or null to clear). Through `taskAuthoringService.update`; marks device sync dirty |
| `task:set-status` | task id, `TaskStatus`, optional folder word (`statusLabelInput`: a string ≤ 200 chars, or nothing) → `TaskDto`. Through `taskAuthoringService.setStatus`, which ends in `taskService.setStatus(…, {manual: true, bound, label})`; it is the only manual caller. Internal callers (runs, handovers, delegations) keep the plain table |
| `task:folder-board` | agent id → `TaskBoardColumn[]` or null (the agent's tasks are not kept in a folder). See [Folder Tasks](../tasks/folder_tasks_tech.md#ipc-channels) |

## Services & Key Methods

- `taskAuthoringService.createRouted(scope, input)` — `prepare` (the validation below), then `localHomeFor(agentId)` for an agent assignee: a local home's task goes to `taskSyncService.createInHome`, every other to `taskService.create`. `create` is the same without the routing. `checkParent(scope, parentTaskId, assignee)` — the parent must exist in the profile, not deleted (`not_found`), not archived, and have the new task's assignee kind and agent (`invalid_input`, thrown as a sentence the dialog shows); one level only stays `taskService.create`'s rule. `setStatus(scope, taskId, status, label?)` sets `bound` from the bound adapter's `capabilities().transitionTable` (a file task moves by the unbound overlay) and checks a label against the agent's folder board before passing it on.
- `taskAuthoringService.prepare(scope, input)` — trims the title (required), defaults goal to the title, status `new`, router `direct`, origin `local`, executor `desktop`, then `taskService.create`. `update(scope, taskId, input)` resolves only the assignee and hands the rest to `taskService.update`. `resolveAssignee`: `null` or `{kind:'model'}` → `{kind:'model', agentId:null, name:null}`; an agent must be found by `agentService.findAgent` across settings and profile scopes and be enabled, the profile's `agentOverrideRepo` value winning over the row's. It is a separate module because `taskService` is imported by the app-sync apply path (`sync/collections.ts`), which must not pull the agent stack in behind it.
- `taskService.update` — `TaskFieldPatch` carries `assignee` (already resolved) and `customFields`. A custom-field edit of a bound task marks `customFields` dirty; the push drops it for a remote whose `writeFields` lack it. An assignee change is gated by `assigneeEditRefusal` (`deviceLocal`, chat, claim/executor, `remoteAdapter`, `router === 'script'`, `taskRuntimeRepo` / `scriptRuntimeRepo.owner`) and clears `assigneeRef`, since the portable descriptor is derived from the row.
- `taskService.setStatus(userId, taskId, status, {manual, bound?, label?})` — `bound` defaults to "has a remote adapter"; `label` is stored as `statusLabel` with the status. After `requireRunsHere`: `manualStatusRefusal` (worded from `canMoveManually`), then a runtime owner, then `activeChatRunId(task.chatId)`, then — for a manual-only close (`isManualOnlyTransition` + `isSettled`) — a linked job run still `pending`/`running`. All throw `TaskError('invalid_transition', …)` with category words (`statusLabel`, `manualRefusal`). Without `manual`, only the plain `canTransition` check applies.
- `taskService.create` validates `customFields` with `checkedCustomFields` (shared `validateTaskCustomFields`, then empty → null).
- `taskService.applyRemoteSnapshot` — a pulled `updatedAt` is taken only when it is not older than the row's own; otherwise the row keeps its time. Taken unconditionally, a pull carrying the remote's older time moved `updatedAt` back below the device-sync watermark, so a local-only edit to a bound task (custom fields, router) was never pushed to the user's other devices.
- `syncedCustomFields(plaintext)` in `sync/collections.ts` — absent key → `undefined` (keep), `null` → clear, a value → `validateTaskCustomFields`; a refused value → `undefined`, never half-applied.

## Renderer Components

- `TasksButton` — 29 px top-bar control, `aria-label="Tasks"`, `aria-pressed` while `activeView === 'tasks'`; renders nothing while `showTasksButton` is false. Mounted in `TopBar` between `SidebarButton` and `AgentStatusButton`, with `TOPBAR_BTN`, so it takes part in the header wave (`.ambient-header-button`).
- `TasksView` — `useTaskList({rootOnly: true})`, `useAgents`, `useFolderBoard(agentId)` while the board is filtered to one agent (the loading line until it answers), `useTaskDispatchList` and `useDispatchControls` for the filtered agent's queue. Filtering is in the renderer, in order: `withinTaskPeriod` (read once per list, with one `Date.now()`), then `matchesTaskFilters` (agent, search); `agentFilterOptions(rows, agentName)` reads the unfiltered rows. The header row: title, the Agents | Recent | Board | List group (`MODES`), `TasksRunNextControl` from `TasksDispatchControl.tsx` when the filtered agent has a queue, a flex spacer, `TasksFilterButton`, New task (its word hidden below `@xl`, `aria-label` and `title` kept). The two absolutely placed `role="alert"` lines sit at `top-full` of the header (a dispatch refusal right-aligned, shown when no move error is; a move error clears it). The `TasksFilterState` it hands the block wraps `setAgent` and `setPeriod` with `clearErrors` (move error and `dispatch.clearError()`); `setSearch` does not. `seenKey` = `` `${agent}:${period}:${searching}` `` keys `TasksAgents`, `TasksRecentList` and `TasksList`, so a filter change, or a search starting or ending, takes the first-seen order again. Content precedence: loading (`tasks.isPending`, or the folder board pending) → nothing when `unread` (`isError` and no `data`; only the **Try again** line below) → `noMatch` (`rows.length > 0 && visible.length === 0`): *No tasks match.* when searching or no row matches the agent at all, else the period's words from `taskPeriodLabel` → *No tasks yet.* → the layout. Owns `useCreateTask` with a hook-level `onCreated` that closes the dialog and opens the task, so a dialog that has unmounted cannot drop it. Scroller marked `data-tasks-scroll`.
- `TasksAgents` (`TasksAgents.tsx`) — the Agents layout: a `@container` grid (one column, two from `@2xl`, three from `@6xl`) of `TasksAgentCard`s, each a `section` with `aria-label` = the card's name (a `region` by that name) and `.app-glass-card` (`src/renderer/src/assets/main.css`: a translucent fill with `backdrop-filter`, a light and a dark variant). Header: `AgentTypeIcon` (which carries the chosen colour) and the name as an underlined button calling `useOpenAgentPage` (plain text for No agent, or an agent missing from the list); the counts are `COUNTED` (waiting/`blocked`, active/`in_progress`, ready/`open`) as `TaskStatusIcon` + number in a `role="img"` span whose `aria-label` and `title` are the sentence, else a round badge with the bare total, `role="img"`, named *N task(s)*. Rows: `useTaskRowsInPlace(card.tasks, CARD_PAGE = 6)` for the first-seen `ordered` only — the card does its own paging: `ordered.slice(0, 6)`, then the rest in an `AnimatedCollapse`, then a centred `aria-expanded` button (`--color-text-secondary`) reading **Show more tasks** / **Show less**. `expanded` = `open && ordered.length > 6`, and an effect resets `open` once the card is down to six. `TaskRow` without the assignee. Takes `agents` from the view rather than calling `useAgents` per card.
- `TasksFilters.tsx` — `TasksFilterButton`: one bordered `h-7` block holding a `role="group"` `aria-label="Applied filters"` of three `FilterPill`s and the trigger (`aria-label="Filters"`, `aria-haspopup="dialog"`, `aria-expanded`, its word hidden below `@xl`). Pills: period (present unless `all`; × → `setPeriod('all')`, labelled `Remove <period>`, `[flex-shrink:0.25]`), agent (`maxWidth` 10rem, × `Remove the <name> filter`), search (`“query”`, 9rem, × `Clear the search`); every × runs `clear()`, which applies and focuses the trigger. `FilterPill` is always mounted: a grid whose column animates `1fr`↔`0fr` with opacity (no transition under reduced motion), `min-w-16` while present; absent it is `aria-hidden` and `inert` and keeps its last words in a ref while it shrinks. The form is `usePopover('below-right')`, portaled to `document.body` (`role="dialog"`, `aria-label="Filter tasks"`): `searchbox` `Search tasks` (focused once the popover is placed), `select` `Agent` (All agents, `agentOptions`, the current agent if it is no longer among them, No agent), `radiogroup` `Changed in` over `TASK_PERIODS`, and the always-shows note. Escape is caught on `document` in the capture phase and returns focus to the trigger; a `scroll` captured on `window` closes it when its target contains the trigger and is outside the form; outside clicks are `usePopover`'s.
- `TasksList` — one section per `LIST_SECTION_ORDER` category through `TasksListRows`; Done pages by 10. `TasksRecentList` — the **Recent** layout: one `TasksListRows` labelled "Recent tasks", sorted by `updatedAt` desc then id before `useTaskRowsInPlace` takes its first-seen order, `RECENT_PAGE` 10; `TasksView` keys it by `seenKey`. Rows are `TaskRow` with `showAssignee` while the filter is All agents.
- `useTaskRowsInPlace(rows, pageSize, newRows?)` — the first-seen order and the in-place Show more shared by these lists, the board's columns, `TaskList` (Subtasks) and `JobDetail`'s Tasks history (`newRows: 'prepend'`). Returns `head` (first page), `more` (the slot holds Show more), `expanded` (the slot holds the inert "All N shown"), `rest` (every other row, rendered below the slot) and `showMore`. No scroll compensation: nothing above the slot moves.
- `TasksBoard` — five `BoardColumn`s (`data-board-column`), or, given `folderColumns`, one per folder word (`data-tasks-board="folder"`, `data-folder-column`, `data-droppable`; columns frozen during a drag; see [Folder Tasks](../tasks/folder_tasks_tech.md#renderer-components)), `BoardCard` (`data-task-card`, draggable only with targets; its status icon wrapper is `relative` and holds the `TaskLiveDot` as an absolute badge when the task has a chat) and `CardMenu` (`role="menu"`, **Move to {column}**). Optimistic overrides are a `Map<taskId, {status, label?, seq, from}>`, cleared by a read showing the written status or any status other than `from`, and per move by `seq` on a refusal.
- `tasksViewModel.ts` — `taskAgentKey` / `agentFilterOptions` (every agent with a task, A→Z) / `matchesTaskFilters` (filter value `all`, `none`, or `agent:<id>`; `none` matches every task without an agent or remote-agent assignee), `TASK_PERIODS` / `taskPeriodLabel` / `withinTaskPeriod(task, period, now)` (`all`, or a Waiting / In progress / Ready category, passes; else `updatedAt` within 7 or 30 days), `agentCards(tasks, agentName)` → `TaskAgentCard[]` (`key`, `agentId`, `name`, `tasks`: one card per agent among the already-filtered tasks, named by the agents list else the task's stored name, A→Z by `localeCompare`, then No agent when an `UNASSIGNED` task is given; each card's tasks by `LIST_SECTION_ORDER`, then `updatedAt` desc, then id), `LIST_SECTION_ORDER`, `isUserColumn`, `boardMoveTargets` (empty unless `executor === 'desktop'`, `runsHere` and no `runtime`; then `manualTargets` with `bound = isTableBound(task)` — `remote` set and no `file` — mapped to other user columns), `folderMoveTargets` / `folderColumnIndex` (the folder board's rules), `taskStatusText` (a task's `statusLabel` as written, else `taskStatusLabel`), `taskFileName`, `customFieldText`, `taskStatusLabel` (the category words, closed split into Done/Failed/Cancelled, `Archived`; unknown strings printed as words), `isUnassigned` (`model` and no `chatId`).
- `TaskFormDialog.tsx` — `NewTaskDialog` (title + Enter; More options; with `parent: NewTaskParent` it is **New subtask**, names "Under <parent> · assigned to <agent>" at the top, locks the Assignee select to the parent's and sends `parentTaskId`) and `EditTaskDialog` (opened from `TaskActionsMenu`'s **Edit task…**, which owns `useUpdateTask` and `useSetTaskStatus` because it outlives the dialog). `assigneeLockReason` and `statusLockReason` mirror main's refusals from the DTO to disable controls; main stays the authority. `editTargets` = `manualTargets` minus a status in the same category; for a file task `statusChoices` offers the folder board's targets with their words instead, and `ReadOnlyFields` lists the file's nested fields, which `fieldsFrom` carries through unchanged. New task's status options take the assignee folder's words (`newStatusWords`). `fieldsFrom` keeps a field's original typed value while its text is untouched, else stores the text; duplicate and empty names are refused before sending. `useDismiss` lets Escape/outside click close only an unchanged, idle form.
- `TaskAssigneeChip` — agent type icon (in its chosen color) and name; nothing for a task without an agent.
- `TaskView` — `customFieldEntries` under a `Fields` section in Details (`Detail asWritten`); for a file task the **File** row (name, Reveal, the changed-outside glyph) and **Blocked by**; assignee **Unassigned** via `isUnassigned`; **Add subtask** beside the Subtasks heading (`subtaskParentOf`: a root task that is not archived and not assigned to a remote agent), whose `useCreateTask` is owned by `TaskView` so its `onCreated` opens the new subtask after the dialog unmounts; the back arrow precedence is Parent task → **Back to Tasks** (when `taskOpenedFromTasks`) → Back to {job} → Back to the Inbox.

## Configuration

- `localStorage['cinna-show-tasks-button']` — `'0'` hides the button; anything else (including absent) shows it. Machine-wide, not per profile; the `storage` listener in `ui.store.ts` applies a change from another window through `setShowTasksButton`.
- `localStorage['cinna-tasks-view-mode']` — `'board'`, `'recent'` or `'list'`; anything else, including absent, opens Agents. A `'list'` stored before Agents existed is honoured, so a user who chose List keeps it.
- No `app_settings` key; the toggle is a renderer preference like Extra UI animation.

## Security

- Both `task:create` and `task:update` payloads are rebuilt field by field in `task.ipc.ts`, never spread; custom fields are re-validated in `taskService` and again on device-sync apply.
- The assignee is resolved and checked in main against the active profile and settings scopes; the renderer sends only an agent id.
- Manual status writes keep `requireRunsHere`, so the claim gates them as it gates every status write.
