## Database Schema

None for voice input's own data. Two app settings in the existing app-settings store: `voiceCloudTranscription` and `voiceCloudProviderId`. The Gemini key is the existing provider row's encrypted key. The two renderer preferences are localStorage: `cinna-voice-input-device` (absent means system default) and `cinna-show-voice-input` (`'1'` shows; anything else, including absent, hides — off by default). `showVoiceInput` is synced across windows through the store's `storage` listener; the device is not.

## IPC Channels

- `speech:status` → `SpeechStatus`: `supported` / `engine` / `reason` / `authorization` / `backend` for the on-device engine (probed once), `available` (`supported`, or cloud mode not off with at least one usable provider) and `cloud` (`mode`, `usable`, `providers`). The cloud half is read fresh from settings and provider rows on every call and decrypts nothing. No activation check: it says nothing user-scoped. The renderer refetches it (`SPEECH_STATUS_QUERY_KEY`) on window focus, on a change of `voiceCloudTranscription` / `voiceCloudProviderId` (its own write, and `settings.onChanged` from elsewhere), and after a provider is saved or deleted or a managed provider event arrives.
- `speech:stream` — **`ipcMain.on`, not `handle`**: the renderer calls `ipcRenderer.postMessage('speech:stream', { locale }, [port])`; the options arrive as the second handler argument and the port on `event.ports[0]` (a missing port is logged and dropped). Frames on the port are typed in `src/shared/speech.ts`:
  - Renderer → main `SpeechStreamCommand`: `audio` (`pcm: Uint8Array`, at most 64 KB per frame), `stop`, `cancel`. A frame that fails `parseSpeechStreamCommand` cancels the session and is answered with a fatal `failed` error.
  - Main → renderer `SpeechStreamEvent`: `start { backend }`, `partial { text }` (the whole current unconfirmed segment, replacing the last), `final { text }` (confirmed, never revised), `engine-change { backend, reason }`, `error { code, message, recoverable }`, `stop { fullText }`.
  - Exactly one terminal event, `stop` or a non-recoverable `error`; main closes the port after posting it. An unactivated session gets a fatal `failed` error frame. The port closing (window gone, reload) cancels the session. Every failure is a frame, never a throw.
- `speech:transcribe` (`TranscribeRequest { wav: Uint8Array; locale? }`) → `TranscribeResult`. Calls `userActivation.requireActivated()`; rejects an empty WAV and one over 32 MB as `failed` data. Every failure is returned as `{ success: false, code, message }`, never thrown, because a thrown error's code does not survive IPC.

## Services & Key Methods

- `speechService.startProbe()` — probes the engines once in order and caches the first supported one; an engine that throws counts as unsupported with its reason.
- `speechService.choose()` — once per session (stream or batch): `always` → Gemini; `fallback` → Gemini only when the probe found no on-device engine; otherwise the on-device engine. A cloud choice with no usable provider ends as `unavailable` with `NO_GEMINI_PROVIDER_MESSAGE`. The `chosenBecause` it passes on (`always`, or `fallback: <probe reason>`) is logged by the engine. Denied authorization is not "no engine". `noteAuthorization` ignores the cloud engine, so a Gemini session never changes the on-device permission record. Settings are read through `cloudConfig()`, whose failure reads as Off.
- `speechService.status()` — the cached on-device status plus the fresh cloud half. While authorization is not `granted`, each read asks the engine's `probe()` again (single-flight) and updates only `authorization`, so returning from System Settings enables the button without a restart. `backend` is the probe-time value and is not refreshed after a model install.
- `speechService.transcribe()` — `unavailable` with no engine, `busy` while that engine already runs one (a transcription or a stream); afterwards a success records `granted` and a `denied` result records `denied`.
- `speechService.openStream(options, sink)` — returns a session at once; the engine is picked when the probe has answered, and audio pushed earlier is queued. `unavailable` and `busy` arrive as fatal `error` events. The engine is marked busy until the terminal event or `cancel`. A `start` event records `granted`, a `denied` error records `denied`. After `cancel` the sink hears nothing.
- `geminiLive.openStream()` — see Gemini Live engine below.
- `macosSpeech.probe()` — unsupported off darwin or when the helper file is missing, without spawning; otherwise `cinna-speech probe` with a 10 s timeout.
- `macosSpeech.transcribe()` — writes the WAV to `tmpdir()/cinna-speech-<uuid>.wav`, runs `cinna-speech transcribe --file` with `transcribeTimeoutMs(wav)` (60 s + 2 × duration from the WAV header's byte rate), and always deletes the file. A timeout reads "took too long"; a SIGABRT reads "no usage description" (see Security); output with `installModel: true` starts `installModel()`.
- `macosSpeech.openStream()` / `openHelperStream()` — spawns `cinna-speech stream [--locale]` and pipes the PCM to its stdin. Main keeps the finals so `stop` carries `fullText`; whatever is still unconfirmed when the run ends normally becomes a last `final` first. Main also owns the endings the helper cannot report: a crash while recording (SIGABRT reads "no usage description", otherwise "stopped unexpectedly"), a helper that does not print `done` within 10 s of the audio ending (finishes with what it has, kills the helper), and the length cap (30 minutes of audio = 57.6 MB; further audio is cut and the session stops as if asked). `cancel` kills the helper with SIGTERM and emits nothing. A helper that exits after `done` or `error` is given 2 s before a SIGTERM. stdout is decoded with one `StringDecoder` per stream so a multi-byte character split across reads is not damaged; lines that are not known events are skipped. `installModel: true` on `start` or `error` starts the same one background install as batch.
- `installModel()` — one background `cinna-speech install` at a time, 15-minute timeout, result only logged.
- `lastJsonLine()` — the helper prints one JSON line, possibly after framework log noise; the last line starting with `{` that parses wins. Malformed output is unsupported (probe) or `failed` (transcribe).

### Gemini Live engine
Facts from a live probe of `gemini-3.5-transcribe-live` (2026-11-11, `@google/genai`, `apiVersion: 'v1beta'`, `responseModalities: [TEXT]`, `inputAudioTranscription` with the locale, audio `audio/pcm;rate=16000` in ~100 ms chunks):
- `probe()` is always supported (`backend: 'gemini-live'`); whether a key exists is settled per session by `resolveGeminiKey()`. No key emits a fatal `unavailable` error and no `start`. `transcribe()` answers `unavailable`.
- **Interim is cumulative within one utterance** (replace, never append; it can shrink, a trailing full stop dropped then restored): it becomes a `partial`. **The final covers one utterance only** (not cumulative): it becomes a `final`, and finals can differ from the last interim. An utterance ends on the server's voice-activity pause; the next interim starts fresh. `voiceActivity` arrives as `{ type }` on the wire although the SDK names it `voiceActivityType`; both are read.
- **After `audioStreamEnd` the pending final arrives in about 0.3 s**; the socket stays open, so main closes it.
- **Stop and settle.** `stop` sends `audioStreamEnd` once the connection is ready (audio pushed before `setupComplete` is queued and flushed first). The connection is finished when it is quiet (no pending interim, no open voice activity) and has sent nothing for a grace (300 ms after live audio, 600 ms when the audio went out in one burst at setup, since the server is further behind). Every message re-arms the grace. A silence of 3 s ends it with what it has, and 10 s is an absolute cap however chatty. Whatever interim is still pending becomes its last `final`. Setup has 10 s. Total audio is capped at 30 minutes, then the session stops as if asked.
- **Rotation.** A connection lasts about 10 minutes. At 9.5 minutes, or on `goAway`, a new connection takes the audio and the old one gets `audioStreamEnd`. **The old connection's words come first**: the new one's events are held until the old has said its last final or timed out, so the text stays in spoken order. Audio is cut at an arbitrary instant, so a word at the seam can be split (known limit). No rotation starts once the user is stopping.
- **Errors.** A close before `setupComplete` whose reason matches key or auth wording (a bad key closes with 1007 "API key not valid") is `failed`: "Gemini rejected the API key of provider <name>". Quota, 429 or resource-exhausted wording is `failed`: the provider's quota is used up. Any other close before setup, a connect failure or the setup timeout is `unavailable` ("Couldn't reach Gemini…"). A close after setup is `failed` ("stopped transcribing unexpectedly"). A close after the end was sent, or during a handover, keeps what was said. All are fatal `error` events, never thrown. A key that no longer decrypts is `unavailable` with a message naming the provider.
- **The key never leaves main**: decrypted per session, held in the session closure, nulled at the end, and `scrub()` replaces it with `[key]` (and clips to 300 characters) in anything the server says before it is logged or shown.
- **Log** (scope `speech-gemini`): one `speech stream finished` line per session with `engine: 'gemini'`, `backend` (`gemini-live`, or `none` when no key), `chosenBecause`, `seconds`, `durationMs`, `locale`, `firstPartialMs`, `partials`, `finals`, `rotations`, `outcome` (`stop`, `stop-timeout`, `cancelled`, `error:<code>`), `capped` (only when hit), `characters`. Also `gemini live connection rotating` (`why`, `from`, `to`), `gemini live connection closed` (`code`, scrubbed `reason`), `gemini live did not set up in time`, `could not connect to Gemini Live`, and the two stop timeouts. No transcript text, no key. Key-reading failures log under scope `speech`.

### The helper's contract
- `probe`, `transcribe` and `install` print one JSON line and exit 0 for every handled case; a non-zero exit means the helper itself broke. `stream` prints one JSON line per event (below) and is the exception.
- `probe` never prompts (it reads `SFSpeechRecognizer.authorizationStatus()`) and returns `available`, `onDevice`, `authorization`, `locale`, `backend`, and on macOS 26 `model` (`installed` | `missing` | `downloading`).
- `transcribe` requests authorization when not determined (the system prompt), then picks the backend: `.ready` → SpeechAnalyzer over the file, falling back to SFSpeechRecognizer on any error (with `analyzerError` in the answer); `.needsModel` → SFSpeechRecognizer, plus `installModel: true` unless a download is already running; `.unusable` → SFSpeechRecognizer.
- SFSpeechRecognizer runs with `requiresOnDeviceRecognition = true` and `addsPunctuation` on macOS 13+; without `supportsOnDeviceRecognition` it answers `unavailable` ("downloading, try again in a minute" while the macOS 26 model installs, otherwise "isn't available on this Mac without sending audio to Apple"). Error 1110 maps to `no-speech`.
- The SpeechAnalyzer code is compiled only under `#if compiler(>=6.2)` and runs only under `#available(macOS 26, *)`; a helper built with an older SDK is SFSpeechRecognizer-only.
- stdout carries only the answer; diagnostics go to stderr as `cinna-speech:` lines (`diagnose()`), so they never compete with the JSON line.
- **`stream [--locale]`**: stdin is raw s16le PCM, 16 kHz, mono, until EOF; stdout is NDJSON, one object per line: `start` (`backend`, optionally `installModel: true`), `partial` (`text`), `final` (`text`), `engine-change` (`backend`, `reason`: SpeechAnalyzer failed to set up, fell back before any audio was read), `error` (`code` `denied` | `unavailable` | `failed`, `message`; ends the run), `done` (every final printed; ends the run). The helper exits 0 after `done` or `error`. EOF on stdin is "stop"; SIGTERM is cancel and the process just dies. Authorization and backend choice are as for `transcribe`; a `streamOutput` lock keeps lines whole and nothing is printed after the last one.
- **SFSpeechRecognizer segments** (the rule the stream depends on): the running text is cumulative, and on-device recognition resets it after about 3 s of pause and about every 60 s. The result delivered just before each reset is the only one carrying `speechRecognitionMetadata`, and it is not marked final; it carries the whole segment, so the helper emits it as a `final`, and later results start a new segment as `partial`s. The `isFinal` result after `endAudio()` is the last segment's `final` (not repeated when it equals the segment just confirmed). Error 1110 ends the stream as `done`, not as an error.
- SpeechAnalyzer streaming: volatile results are `partial`s, final results are `final`s. Setup failures before any audio was read become `engine-change` plus an SFSpeechRecognizer run; a failure after audio flows is an `error`. This path has never been executed.
- `probe` reports `available` from `SFSpeechRecognizer.isAvailable` and does not require an on-device model, so the button can show for a language whose every transcription will then be refused.

### Diagnostic log lines
A "No speech was detected." toast has two possible causes — the recording was silent, or the recognizer heard nothing in real audio — and the log exists to tell them apart. Both halves show in the in-app logger (⌘`).
- **Renderer, scope `voice`** (`useVoiceRecorder`): `microphone opened` (track label, whether a device was chosen, sample rate, channel count, `muted`, `readyState`); `microphone track muted` / `unmuted` / `ended while recording`, only while the session is live; `chosen microphone failed to open, using the default`; `could not start recording`; on stop, `recording stopped` with `seconds`, `sampleRate`, `chunks`, `peak`, `rms` — logged as a warning `recording got no audio from the recorder` at 0 chunks, or `recording is silent (peak below 0.0001)` at a zero peak; `transcription failed` with `code` and `message`.
- **Main, scope `speech-macos`** (`macosSpeech.transcribe`): one `speech transcription finished` line per run with `backend`, `seconds` (from the WAV header), `locale` (`system` when none), then `ok` + `characters` or `ok: false` + `code`, and `stderr`. A helper that did not exit 0 logs `speech transcription failed` with the same `stderr` instead. `helperStderr()` keeps every `cinna-speech:` line plus the last 3 other lines (framework noise), capped at 800 characters.
- **Live dictation** (no transcript text anywhere in any of these):
  - Renderer, scope `voice`: `dictation engine started` (`backend`), `dictation engine changed` (`backend`, `reason`), `dictation engine reported a recoverable error`, `dictation failed` (`code`, `message`), `dictation finished` (`backend`, `characters`), `dictation did not finish in time`; plus the shared `microphone opened` (which now also carries `streaming`) and the `recording …` lines on stop.
  - Main, scope `speech-macos`: one `speech stream finished` line per session with `backend`, `seconds`, `locale` (`system` when none), `firstPartialMs`, `partials`, `finals`, `outcome` (`stop`, `stop-without-done`, `cancelled` or `error:<code>`), `capped` (only when the cap hit), `characters` and `stderr`. A session that never started (not macOS, no helper) logs the same message with `backend: 'none'` and `seconds: 0`. Also `speech helper exited while recording`, `speech helper did not finish after the audio ended`, `speech helper failed`, `speech helper did not start`, and `SpeechAnalyzer failed, fell back to SFSpeechRecognizer` (`reason`).
  - Main, scope `speech-ipc`: `speech:stream arrived with no MessagePort`, `speech stream: off-contract command, ending the session`.
  - Helper stderr adds `stream: backend …` lines and `stream: end of audio after N s`.
- **Helper stderr**: the chosen backend with the locale (or the analyzer model `downloading`/`missing` when it fell back to SFSpeechRecognizer) and the input's format (`16000 Hz, 1 ch, 2.40 s`); on the analyzer path, `analyzer read to the end` or `found no audio to read`, and how many results it produced; `SpeechAnalyzer failed, using SFSpeechRecognizer: …` on a fallback.

Reading them: 0 chunks or a zero peak means the audio never arrived — microphone permission, the wrong device, or a track macOS muted or ended — and the recognizer is not at fault. A non-zero peak with `backend analyzer` and `0 result(s)` points at the macOS 26 SpeechAnalyzer path. Running `cinna-speech transcribe` from Terminal does not reproduce this: it stops at the speech-permission step (Terminal is the responsible process, see Security), so the in-app log is the way to see the helper's side.

## Renderer Components

- **`VoiceInputButton`** returns null unless `status.available && showVoiceInput`; otherwise `VoiceInputControl`. Classes: idle muted, blocked dimmed (`speechBlocked`: denied or restricted, ignored when cloud is Always or there is no on-device engine, since the permission does not apply), recording `--color-danger` with `motion-safe:animate-pulse`, transcribing a spinner with `disabled`.
- **Send after text.** A headphone double click sets `sendAfterText`; `handleText` consumes it and bumps `landed`; an effect on `landed` calls the latest `onSend`, so Send runs after the commit that put the dictation in the draft. Any error clears the flag, and so does the recorder returning to idle, so a stale double click cannot make the next dictation send itself. `send()` reads `current()`, not the rendered state.
- **Hide.** `hide()` sets `showVoiceInput` false, focuses the composer, and shows an `info` toast linking to `features`, mentioning a discarded recording when one was running.
- **Live dictation wiring.** `VoiceInputControl` builds the `DictationCallbacks`: `onSessionStart` reads the textarea's selection into a `DictationSpan`, publishes it to `liveDictation.store` under the draft key and focuses the textarea (typing must reach the composer to freeze the dictation); `onFinal` writes the text through `dictation.setDraft` with `commitFinal` and moves the span; `onPartial` only updates the published partial; `onSessionEnd` clears the entry, and when the engine's own `stop` ended it and a send is pending, bumps `landed` as the batch path does. `controls.freeze` writes the engine's whole partial (not only the typed-out part) into the draft as a final and calls `end()`; `controls.cancel` drops the partial and calls `end()`; `controls.send` is `send()`. The textarea's text is transparent during a live dictation (`data-dictating`), with `DictationMirror` laid over it; the composer's height and its Send-disabled and Stop checks read the shown text, not only the draft, so Send is live while the first words are still only a partial.
- **`useVoiceRecorder`.** idle → recording → transcribing → idle. With `dictation` and `speech.stream` present it opens the stream before the mic, so the engine starts while the mic warms up; without either it takes the batch path. Live stop waits 50 ms, releases the mic, flushes the partial chunk, cancels instead of stopping under a quarter second ("Nothing was recorded."), and arms a 20 s timer ("Transcription took too long."). A fatal event ends the session with the error toast. Unmount during recording cancels and ends the session; unmount while finishing leaves it to deliver. Batch details: Stop waits 50 ms for the worklet's queued blocks, releases the mic and context, and refuses under 4000 samples (a quarter second) with "Nothing was recorded." A remembered device that is gone, or vanishes between check and open, falls back to the default. Unmount releases everything and discards a recording; a transcription in flight still calls `onText`.
- **`mediaKeys`.** A stack of registrations; the top one (most recently mounted, focused composer, or clicked button) receives `play`/`pause`/`stop` → toggle and `nexttrack` → send. While at least one is registered and the window is focused, `silence.wav` (7 s of zeros; Chromium wants ≥5 s to treat it as media) loops and `playbackState` is `playing`; blur or the last unregister pauses it and clears the handlers. No `globalShortcut`, which would need the Accessibility permission.
- **`useSpeechStatus`.** TanStack query, `staleTime: Infinity`, `refetchOnWindowFocus: 'always'`, `retry: false`. A missing `window.api.speech` or a malformed answer is unsupported, which keeps tests and older preloads working.
- **`useVoiceErrorToast`.** Shows `kind: 'error'`, `link: null`; `null` dismisses only if the store's current toast id is the one it showed.

## Configuration

- Build: `scripts/build-speech-helper.sh` (also `make speech-helper`), run by `build:mac`, `build:mac:unsigned`, `release:mac`, `release:all` and `scripts/bare-mac/package-app.sh`. Universal arm64 + x86_64, deployment target macOS 12, ad-hoc signed with identifier `io.opencinna.desktop.speech` (electron-builder re-signs it). No-op off macOS. The macOS 26 path needs the macOS 26 SDK from Xcode 26; with an older SDK (the Command Line Tools stop at 15.x) the script warns and builds SFSpeechRecognizer only. Packaging rules: [Release & Distribution](../../development/distribution/release.md#voice-input-helper).
- Helper location: `Resources/speech/cinna-speech` when packaged, `<appPath>/resources/speech/cinna-speech` in development, both through `runtimeHost`.
- Cloud: settings `voiceCloudTranscription` (Settings › Features, default `off`) and `voiceCloudProviderId` (empty = first usable). Gemini timers: 10 s setup, 9.5 min rotation, 300/600 ms grace, 3 s silence, 10 s cap, 30 min audio.
- Timeouts: probe 10 s, transcription 60 s + 2 × recording, model install 15 min. IPC cap 32 MB. Live: 30 min of audio, 10 s for the helper's `done` after the audio ends (main), 20 s for the whole finish (renderer), 64 KB per audio frame.

## Security

- Recognition is on the device only unless cloud transcription is on (see the business rules); Gemini audio goes to Google over the user's own key, which stays in main (see Gemini Live engine); the temp WAV is deleted after every run, success or not.
- The stream port accepts only the three command shapes and bounds each audio frame, and the preload drops any event frame that fails `isSpeechStreamEvent`. The log never carries the transcript: main logs its character count, the renderer and the helper only levels, formats and counts.
- **TCC charges speech recognition to the responsible process, not the helper.** The packaged app declares `NSSpeechRecognitionUsageDescription` and is responsible for the helper it launches. A development build started from a terminal (`npm run dev`) makes the terminal app responsible; it has no such string, so macOS kills the helper with SIGABRT and the toast says "no usage description". Dev mode therefore cannot transcribe — test with a packaged build launched by `open`. Crash reports land in `~/Library/Logs/DiagnosticReports/cinna-speech-*.ips`; their `responsibleProc` names the app TCC charged. A private macOS call could make the helper its own responsible process; it was deliberately not used.
- The hardened runtime blocks the microphone without `com.apple.security.device.audio-input`, whatever the user answers in the prompt.
- Microphone labels are empty until the Microphone permission is granted, which is why the menu numbers unlabelled inputs and shows only System default at first.
