# Writing E2E Tests (LLM reference)

Concise rules for adding a Playwright spec under `e2e/` that drives the built Cinna Desktop app. Product context: [End-to-End Tests](e2e.md). Read both before writing.

## Commands

| Command | Does |
|---|---|
| `make e2e` | `electron-vite build` then every spec. Run this before declaring done |
| `make e2e-one SPEC=<file stem> GREP="<title fragment>"` | One spec / one test against the existing `out/` |
| `make e2e-only` | Every spec, no rebuild. **Rebuild after any `src/` change** — specs run `out/`, not `src/` |
| `make e2e-live` | Only `live.spec.ts`; needs `OPENAI_API_KEY` in `.env` |
| `make e2e-integration` | Only `cinna-integration.spec.ts`: a **running cinna-core** plus the real cinna-cli. Needs `CINNA_E2E_SERVER_URL` / `_EMAIL` / `_PASSWORD` in `.env`. Excluded from every other run by `testIgnore` unless `CINNA_E2E_INTEGRATION=1`, because it really installs a toolchain and really creates an account workspace |
| `make e2e-ui` / `make e2e-trace TRACE=…` | Step through a run / open a failure's trace |
| `npm run typecheck:e2e` | Types for `e2e/**` (includes `window.api` from `src/preload/index.d.ts`) |

Filter noisy output: `2>&1 | grep -v "Electron Security\|Debugger\|nodejs.org"`.

## Anatomy of a spec

- Import `test`, `expect` from `../fixtures/app` — never from `@playwright/test` directly (the `cinna` fixture is what launches the app).
- One `test()` per scenario, titled with the manual-plan ID when there is one: `test('C5 blocked really means blocked', …)`. Multi-step scenarios use `test.step`.
- The `cinna` fixture (`e2e/fixtures/app.ts`): `cinna.page` (main window), `cinna.electronApp`, `cinna.sandbox` (`root`, `home`, `userData`), `relaunch()`, `stubDirectoryPicker(dir)`, `skipOnboarding()`. Options: `test.use({ engine: true })` when a folder agent must *answer*; `test.use({ launchArgs: [...] })` for argv the app reads at startup (the `cinna://` deep link); `test.use({ env: {...} })` for environment the app reads at startup (`OLLAMA_HOST`), applied to `relaunch()` too and applied *before* the sandbox's own `HOME` / `CINNA_USER_DATA`, which cannot be overridden from it. `relaunch(extraArgs?)` starts *without* `launchArgs` unless given its own — a restart is not a second link click. A value only known in `beforeAll` (a port a spec's own server just bound) is passed as a module-level object that `beforeAll` fills in: `test.use` keeps the object by reference and the fixture reads it at launch (`ollama-credential.spec.ts`). Prefer this over assigning `process.env` in a `beforeAll` — the fixture copies `process.env` wholesale, so that form leaks into every app every later spec in the worker launches.
- `answerAgentsFolder(cinna)` (`e2e/fixtures/app.ts`) — call it after opening the Agents tab when a spec needs the default folder home. Fresh profiles permit external agents without a folder, so opening Agents alone does not show a folder dialog. The helper explicitly clicks **Set one up**, then **Create folder**, and waits for the dialog to close. It checks `rootsList()` and the sandbox home path first and does nothing when a root or home already exists. The created root must remain under the fixture HOME.
- Arrange helpers: `e2e/fixtures/seed.ts` (`addAgentRoot`, `createFolderAgent`), `e2e/fixtures/live.ts` (`requireLiveKey`, `OPENAI_API_KEY`), `seedOpenAiDefaultMode` and `sendFirstMessage` in `live.spec.ts`.
- Cross-repo helpers: `e2e/fixtures/liveCinna.ts` — `requireLiveCinna()` (skip without `.env`), `preflight()` (checks the instance can serve the run and names what is wrong when it cannot), `approveDesktopAuth()` (does over the API the one thing a human does in a browser: approve the desktop's authorization).
- Sandbox is deleted after a pass and kept after a failure (path in the test's annotations).

## Procedure for a new scenario

1. **Pin the observable.** Write down the exact user-visible strings the scenario is about. Find them in `src/renderer/src/**` (`grep -rn "aria-label=\|title=\|placeholder=" …` or the literal text). Zero `data-testid` exist; use roles, names, placeholders, text. Prefer fixing an `aria-label` in the product over adding a test id.
2. **Arrange over IPC, act through the UI.** Seed state with `page.evaluate(() => window.api.…)` — same code path the UI uses, seconds instead of click choreography. Drive only the step under test through the UI. Main-process seams via `electronApp.evaluate(({ dialog, app, Menu, safeStorage }) => …)`.
3. **Assert exact text** with `toHaveText` / `toBe`. Expected-to-fail defects: `test.fail()`. Not reachable yet: `test.fixme(true, reason)`. Missing prerequisites: `test.skip(cond, reason)`.
4. **Run it twice** (`make e2e-one …`), then the full suite. If the spec guards a fix, revert the fix temporarily and confirm the spec fails (copy the file aside first; never `git checkout` an uncommitted fix).

## IPC catalogue for arranging

| Need | Call |
|---|---|
| Agents root under sandbox `$HOME` | `addAgentRoot(cinna)` (stubs the OS picker; roots outside `$HOME` are refused) |
| Folder agent | `createFolderAgent(cinna, root, name)` → `LocalAgentDto` (`id = folder:<uuid>`, `path`) |
| Edit a manifest field | `localAgents.get(id)` → `.value.stamps['cinna-agent.json']` → `localAgents.updateField({ agentId, update: { field, value }, expectedStamp })`; both return `{ ok, value | message }` |
| Edit a prompt document | `localAgents.readDoc({ agentId, prompt: 'workflow' \| 'entrypoint' \| 'refiner' })` → `.stamp` → `updateField({ …, update: { field: 'prompt', prompt, value } })` |
| Re-index from disk | `localAgents.rescan()` — startup does **not** scan; call it after a relaunch before asserting on anything derived from the index |
| Switch an agent off | `agents.setEnabled(id, false)` |
| Job bound to an agent | `jobs.create({ type: 'local', title, prompt })` then `jobs.setAgents(job.id, [agentId])` (`agentId` on create is ignored) |
| MCP dependency | `mcp.upsert({ name, transportType: 'stdio', command, args: [], enabled: false })` — **`enabled: false`**, or the upsert spawns the command and waits; then `jobs.setMcpProviders(jobId, [id])` |
| Run a job / see runs | `jobs.execute(id)` (rejects when blocked) · `jobs.listRuns(id)` |
| Provider + default mode | see `seedOpenAiDefaultMode` — model must come from `providers.listModels()`, not from the live probe |
| A credential with no live key | `providers.upsert({ type: 'anthropic' \| 'openai', name, apiKey: '…', enabled: true })` — `hasApiKey` is true from the row alone, but its **model list is a live call** (see Gotchas) |
| An agent's runtime block | `localAgents.updateField({ agentId, update: { field: 'runtime', value: { engine, credential, modelId, complexity } }, expectedStamp })` — writes `runtime: {engine, credential, model, complexity}` into `cinna-agent.json`; every one of the four is **required** (an omitted `engine` erases the user's engine choice) and a null one removes its key. `engine: 'claude'` with a non-null `credential` is refused — the two are not meaningful together |
| What this machine has installed | `localTools.list()` → `DetectedTool[]`; real detection over the sandbox's rc-file `PATH`, so `claude` / `opencode` / `git` answer as they do on the developer's machine. `test.skip(tool === undefined, …)` rather than faking it. `localTools.claudeAuth()` answers whether the detected `claude` is logged in — real, free (`claude auth status` runs no turn), and **logged out under the sandbox `HOME`** |
| Whether that `claude` is logged in | `localTools.claudeAuth()` → `ClaudeAuthStatus` (`{ state: 'logged_in' \| 'logged_out' \| 'unknown', authMethod, subscriptionType }`); spawns `claude auth status`, which runs **no turn and bills nothing** — the one `claude` invocation a spec may cause. Under the sandbox `HOME` it answers `{ state: 'logged_out', authMethod: 'none', subscriptionType: null }`, on a logged-in developer machine too (see Gotchas) |
| A **bare** agent's runtime | `localAgents.setRuntime(agentId, { credential, modelId, complexity })` — no stamp (there is no manifest to guard); lands in `userData/external-agents/<folder basename>-<16 hex>.json` under `runtime`, never in the folder |
| A log entry with a payload | `logger.log({ level, scope, message, data })` — goes through redaction and the live broadcast |
| Engine | `engine.start()` → `{ status, binarySource, error }` · `engine.skips()` |
| A `cinna://` deep link | `test.use({ launchArgs: ['--cinna-connect-intent=cinna://connect?server=https://host'] })` — the test-only argv form (`src/shared/connectIntent.ts`); `open-url` cannot be raised from Playwright. Inspect/clear the buffer with `connect.getPending()` / `connect.consume()`. Never click **Connect**: it opens a real browser |
| Delete an agent | `localAgents.delete(id)` → `{ ok: true, value: { agentId, trashed } }` or `{ ok: false, code: 'not_found' \| 'turn_in_progress' \| 'write_failed', message }`; calls `shell.trashItem`, then rescans and prunes the row — **stub `trashItem` first** (see Gotchas) |
| Name-only create | `localAgents.create({ name, rootId })` with no `description` → DTO whose `description === name`, `readiness: 'ok'`, `readinessReason: null` |
| The paste-anywhere briefing for an agent | `localAgents.initPrompt(agentId)` → the string the Open-in menu copies; names the folder and the first entry document that exists (`AGENTS.md` → `CLAUDE.md` → `README.md`), and throws `not_found` when the folder is gone |
| An agent's standing permission grants | Write the folder's own store: `<agent.path>/app-data/desktop.json` (`DESKTOP_STATE_FILE` in `src/shared/kit/manifest.ts`) as `{"permissionGrants": {"<action>::<pattern>": {action, pattern, scope: 'exact'\|'origin'\|'action', decidedAt}}}` — main derives the folder from the agent id, so there is no seeding IPC. Read back: `localAgents.grantsList(agentId)` · revoke: `grantForget(agentId, key)` / `grantsClear(agentId)`, both answering with the list they leave |
| Local development state | `localDev.getState()` (`{ phase: 'idle' }` for a non-Cinna profile) · `localDev.consent(host, false)` / `getConsent()` / `resetConsent(host)` — persisted in the `localDevConsent` app setting, so they survive `relaunch()` |
| A folder agent that **asks** mid-turn | `installFakeAcpEngine(cinna, script)` (`e2e/fixtures/fakeAcpEngine.ts`) — sets `localAgentsEnginePath` to a `/bin/sh` shim that answers `--version` and then `exec`s `src/main/agents/drivers/acp/testSupport/fakeAcpAgent.mjs`, the same scriptable ACP agent the driver's unit suite drives, so the app spawns it exactly as it would `opencode acp`; kept in the profile, so it survives `relaunch()`. The shim exports `FAKE_ACP_SCRIPT` / `FAKE_ACP_LOG` **itself**: the launcher builds the child's whole environment and passes it verbatim, so nothing the test process sets reaches the fake. The script (`FakeAcpScript` in `testSupport/fakeAcp.ts`) is written into the sandbox, one per test, and says what `session/prompt` emits — `{kind:'permission', toolCall, options}`, `{kind:'elicitation', params}`, `{kind:'update', update}`; a `request`/`permission`/`elicitation` step **blocks until the client answers**, which is what parks the turn. Still needs a credential with a model or the OpenCode launcher refuses before any fake is reached: a keyless `ollama` row whose `baseUrl` is a `/api/tags` fake the spec owns, plus `chatModes.upsert({ …, isDefault: true })` (`run-events.spec.ts`) |
| What the agent was sent, and what it was answered | the handle `installFakeAcpEngine` returns: `received('session/prompt')` (what arrived, in order, across restarts) and `answers('session/request_permission')` / `answers('elicitation/create')` — the client's own reply to a request the agent sent, which is the only witness for an answered ask (`{outcome:{outcome:'selected',optionId:'once'}}`, `{action:'accept',content:{question_0:'Teal'}}`). Read `entry.result`; the log is JSONL under the sandbox root |
| A task bound to a chat | `seedChatTask(cinna, { chatId, title, status? })` (`e2e/fixtures/seed.ts`) — no task-creation IPC exists, so it inserts a `completed` desktop task through a second handle on the sandbox DB (refuses any other `userData`) |
| An ACP agent whose traffic the test times | `scriptAcpEngine()` (`e2e/fixtures/scriptAcpEngine.ts`): `customConfig(cinna)` is a command-line agent config (custom launcher, no credential) running `scriptAcpAgent.mjs`; `install(cinna)` is the OpenCode-engine form. Each prompt is held until `calls[i].release(text \| { text?, updates?, after? })` — `updates` are bare `session/update` payloads sent first; `after: true` makes the agent ask again once the prompt returned, held in `afters[i]` until `release({ updates })` (a task ending, a turn nobody prompted). `_session/async_task/stop` is held in `stops[i]` (`params` = `{ sessionId, asyncTaskId }`) until `release({ updates, result })`. `inits` holds each process's `initialize` params — the witness for advertised `clientCapabilities`. Replay the recorded frames in `src/main/agents/drivers/acp/__fixtures__/claude/*.json`, split at `promptReturnedAtIndex` (`session-activity.spec.ts`) |

## Gotchas that have already cost time

- **Agent Settings retains the hidden composer to preserve its draft.** Readiness text can therefore exist in both the hidden composer and the visible Overview. Scope the settings assertion to `getByRole('tabpanel')`; a global exact-text locator can match both.
- **Selection colors need computed-color assertions.** In dark theme, compare an unselected agent name to the resolved `--color-text-secondary` token, select it and compare to `--color-text`, then select another row and check it returns to secondary. A primary color on the inner span overrides a correct row class; checking class presence alone misses this bug (`agent-landing.spec.ts`).

- **A spec holding a fake key must stub the transport, or it calls the real vendor.** `credential-switch.spec.ts` kept two fake keys off the internet by pointing `ANTHROPIC_BASE_URL` / `OPENAI_BASE_URL` at a closed loopback port. When the adapters were pinned that guard went inert and it sent both keys to `api.anthropic.com` and `api.openai.com` on every run — **passing throughout**, because its assertions never touch a catalogue, so nothing failed to say so. It uses `stubLlmFetch` now, which is the only option for a spec that is *about* keyed credentials: there is no base URL left to move, and `providerService.upsert` refuses `baseUrl` on a keyed row. The general rule is the one worth keeping: a passing spec is not evidence that nothing left the machine.
- **Never hold `page` across `relaunch()`** — read `cinna.page` at each use. A destructured `page` targets a closed window and every assertion after it silently fails.
- **`firstWindow()` is the tray panel**; the fixture already picks `index.html`. The tray window is `electronApp.windows().find(w => w.url().endsWith('trayPanel.html'))`.
- **Agents seeded over IPC are invisible to the composer and the job picker** until `relaunch()` — their query is stale and nothing invalidates it. (Since the agent-page refactor the folder watcher's push also refreshes that query, but the push is debounced and not something a spec should wait on; `relaunch()` remains the reliable arrangement.)
- **No `require` inside `electronApp.evaluate`.** The main bundle is ESM, so `require` is undefined and `import()` fails with `A dynamic import callback was not specified`. Use `process.getBuiltinModule('node:fs')`. A stub that throws for this reason is caught by `localAgentService.delete` and comes back only as `write_failed` — the confirm dialog just stays open and nothing says why.
- **Any delete test must stub `shell.trashItem`**, or the sandbox folder lands in the developer's real Trash: `electronApp.evaluate(({ shell }) => { shell.trashItem = async (p) => process.getBuiltinModule('node:fs').rmSync(p, { recursive: true, force: true }) })` — see `stubTrash` in `agent-page.spec.ts`. The ESM `shell` binding is the same object the evaluate receives, so the assignment is seen (same mechanism as the `dialog` stub).
- **The `+` form creates into `roots[0]`**, which on a fresh profile is the default home `~/Documents/CinnaAgents` under the sandbox `$HOME` — not an `addAgentRoot` root. Read the new folder's path from `localAgents.list()` rather than assuming the added root.
- **Rebuild before blaming the product.** `out/` can be older than `src/` when others are editing; compare `stat` times (or grep the bundle for the string) before recording a sidebar/page mismatch as a defect.
- **A folder renamed inside `Local/` is the same agent** (identity is the manifest id). To make an agent *missing*, move the folder out of the root while the app is closed.
- **Log rows are six adjacent spans with no whitespace**; filter `[data-log-index]` by fragments, not by the spaced text.
- **Startup race on the new-chat screen**: a send in the first moment after launch is refused with "no chat mode configured"; use `sendFirstMessage` (retries that one refusal). No other `waitForTimeout` in the suite — every wait is a web-first `expect`.
- **`getByText` matches concatenated text content**, and `getByRole('alert')` may match more than one banner. Scope to a container.
- **Keychain**: the fixture passes `--use-mock-keychain`; do not remove it. Without it `safeStorage` fails under a sandboxed `HOME`.
- **A run does not take the foreground**, by design: the fixture sets `CINNA_BACKGROUND_WINDOW=1` and the app goes `accessory` + `showInactive`. Do not remove it to make a window appear, and do not write an assertion that depends on focus or on the app being active — Playwright drives over CDP, and screenshots render fine without it. To *watch* a flow, use `make demo-localdev`, which deliberately does not set the flag.
- **`uv`, `opencode` on PATH inside the app** come from the sandbox's rc files the fixture writes; the test process's `PATH` is what the app sees.
- **The welcome step already says "Connect to a Cinna instance…"**, so a "no confirm panel" assertion must use the panel's own exact strings (`Connect to <host>?`) or a control only it renders (the **Enable local development** checkbox), not `/^Connect to /`.
- **A Cinna account cannot be arranged in an ordinary spec**: `auth.register({ accountType: 'cinna' })` runs a browser OAuth round trip against a real instance, so everything gated on `user.type === 'cinna_user'` (the local-dev reconciler past `idle`, sync, account config) is out of reach. The answer is a real instance supplied out of band — `make e2e-integration` and `cinna-integration.spec.ts`, which stands in for the browser's *approve* click over the API — never a product-side test hook.
- **`provider:list-models` is a live network call per credential** — every adapter's `listModels()` is one, so two credentials with fake keys give a spec an *empty* registry, and an empty registry makes the Runs-with panel's model rules decline to answer (`modelBelongsElsewhere` never calls an unlisted model foreign). **Stub the transport, not the base URL**: `stubLlmFetch(cinna, { anthropic, openai })` (`e2e/fixtures/llmFetch.ts`) swaps `globalThis.fetch` in the main process, answers both vendor hosts in-process and passes everything else through. **Re-install after every `relaunch()`** — it lives in the app process. Why this and not a redirect: both SDKs resolve `fetch` from the global at client construction and `providerService` builds a fresh adapter per call site, so a stub installed before the call is the one used; it sits below the adapter and so survives base-URL pinning; and it is what `anthropic.test.ts` / `openai.test.ts` already do one level down. **The old `ANTHROPIC_BASE_URL` / `OPENAI_BASE_URL` trick is dead and must not be revived** — `18e97b2` and `167ed6c` pinned both adapters precisely so a shell variable cannot send a stored key somewhere the user never configured. It also failed *open* on its way out: the stub server sat unvisited, `listModels()` answered `[]`, and specs went on asserting a healthy credential branch until an unrelated assertion happened to name a model. Make a catalogue fixture name something only the stub can produce, so it fails closed. A keyless `ollama` row against a fake daemon is the other option and is enough for **one** catalogue (`claude-engine.spec.ts`); it cannot serve a spec needing two, or one that is about keyed rows, because `providerService.upsert` drops `baseUrl` for every type that requires a key.
- **The real clipboard is readable, and is the machine's own**: `electronApp.evaluate(({ clipboard }) => clipboard.readText())` sees what the renderer's `navigator.clipboard.writeText` just wrote — the background window (`CINNA_BACKGROUND_WINDOW=1`) does not block the write. It is the *developer's* clipboard being overwritten, by the product's own action; do not add a test that writes to it for no reason.
- **A sidebar agent row is named only by its agent name.** Status, readiness and description sub-lines are absent. Use `getByRole('button', { name: NAME, exact: true })`; a separate hover/focus chat shortcut also includes the name. Row selection opens chat mode; press the page's `Settings` button before looking for runtime controls or detail tabs.
- **A revoke on the Permissions card empties the list without proving anything.** Both grant mutations answer with the list they leave and the hook writes it straight into the query cache, so a handler that never touched `app-data/desktop.json` still clears the rows and the badge. The assertion that means something is `readFileSync` on the folder's `desktop.json` — verified by mutation: skipping the write in `forgetAllPermissionGrants` passed every UI assertion in `agent-permissions.spec.ts` and failed only the disk read. `forgetAll` leaves `"permissionGrants": {}` rather than removing the key, so assert on `Object.keys(...)`. The `Approvals` select on the Claude branch is the same shape: `useSetClaudeApproval` writes the answered DTO into the agent's query, so the control reads whatever main *says*, and the witness is `claudeApproval` in that same `desktop.json` (the scaffold writes **no** `desktop.json` at all — `existsSync` first) plus the select reading it again after `relaunch()`. Verified by mutation: skipping the `desktopStateService.patch` in `setClaudeApproval` snaps the select back to `auto` on the round trip, because the re-scanned DTO carries `null` (`claude-approval.spec.ts`).
- **Credentials seeded over IPC are as stale as agents.** `providers.upsert` after the window is up does not reach `useProviders` / `useModels` — nothing invalidates them — so the agent Settings `Runs on` select renders only its `Default (…)` option and the panel reads as "this profile has no credentials". `relaunch()` after seeding, before opening the agent page (`agent-runtime.spec.ts` and the bare-runtime test in `bare-agent.spec.ts` both do).
- **Adopting a folder writes no bare state file at all** when every found agent is wanted: `addAgentFolder` skips the `hidden: !wanted` patch for a folder whose state already reads that way, so `userData/external-agents/` is *empty* until the user makes a real choice. Worth asserting — it is the strongest form of "nothing was written anywhere".
- **A card header's file button is named by the file, not by the action**: `AgentCard` renders `<button title="Reveal AGENT.md">AGENT.md</button>`, and visible text beats `title` for the accessible name. Query `getByRole('button', { name: 'AGENT.md', exact: true })` and assert the `title` separately.
- **"Nothing is written into the adopted folder" needs a disk witness, not a UI one.** Every screen in the adopt flow looks identical whether or not the desktop dropped `app-data/desktop.json` into the user's repository — a bare agent's state deliberately lives under `userData/external-agents/`. Snapshot `readdirSync(dir, { recursive: true })` before the flow and compare after: pointing `desktopStatePath` back into the folder failed exactly the three tests carrying that snapshot and none of the others.
- **A folder adopted over IPC is visible without a relaunch** *if* the Agents sidebar has not been opened yet: `LocalAgentsList` only mounts on that tab, so `folderPick` → `folderAdd` then clicking `Agents` fetches the list fresh. (`local-agent:folder-add` refuses a `path` that was not the last one `folder-pick` saw, so the two must be called as a pair, with the OS picker stubbed at that folder.)
- **Resizing to the minimum window: `page.setViewportSize`, not `win.setBounds`.** The app's minimum is 800px (`MIN_WINDOW_WIDTH` in `src/main/window/windowState.ts`) and copy has to be checked there, but under `CINNA_BACKGROUND_WINDOW=1` a `setBounds` on the BrowserWindow does not resize the renderer — the run looks like it passed at 800px and measured the full width. Playwright's `setViewportSize` (CDP `Emulation.setDeviceMetricsOverride`) does resize it.
- **`relaunch()` is too slow to prove a save made on the window's `close`.** Playwright spends over 500ms tearing down before its `close()` calls `app.quit()` (measured: 518ms from a resize to `before-quit`), so a debounced write — `window-state.json` debounces 500ms — has always landed by the time the window closes, and a spec whose `close` listener was stripped still passed. To prove the close path, resize and `win.close()` in **one** `browserWindow(page)` evaluate (the user's red button / Cmd+W; on macOS the app stays alive), poll `cinna.page.isClosed()`, read the file, then `relaunch()` (`window-state.json` covers both paths; stripping `close` listeners fails only the close step). Main-window size: `electronApp.browserWindow(cinna.page)` → `getSize()` / `getNormalBounds()`, never `BrowserWindow.getAllWindows()[0]`, which can be the tray panel. `win.setSize` *does* resize the renderer here (`window.innerWidth` follows). Restart surfaces: the sidebar toggle is a top-bar button named by its title, `Collapse sidebar` / `Open sidebar`, and the collapsed sidebar is `opacity: 0; width: 0` (`.app-sidebar-wrap.is-collapsed`), which Playwright still calls visible — assert the toggle's name and `toHaveCSS('opacity', …)` on `.app-sidebar-wrap`, not the `Chats` tab. The new-chat screen is `heading` level 1 `What can I help with?`; Settings opens on `heading` level 1 `Chat Modes`.
- **Truncation is `scrollWidth` vs `clientWidth`, and `line-clamp` needs the *height*.** A clamped third line is hidden rather than scrolled, so a width comparison passes on text that is being cut. Assert `scrollHeight <= clientHeight` for any multi-line reserved slot, and check the **longest** string that can appear there rather than the one easiest to trigger.
- **A screenshot is not an assertion, and taking one is not reading it.** Both are useful for *finding* a problem and neither proves anything: capture the file, then actually open it, and turn whatever it shows into a locator or a measurement. A spec that only writes PNGs passes while the screen is wrong.
- **Forgetting an agents root is a list-side act, and the folder is the witness.** `local-agent:root-remove` drops the `agents` rows under the root (and everything cascading off them) and touches no file, so every UI assertion in that flow — the row leaving, the agents leaving — would pass just as well against a Forget that deleted the folder. Snapshot `readdirSync(root.path, { recursive: true })` before the confirm and compare after (`forget-agent-root.spec.ts`); re-adding the same path through `Add an agents folder` with the picker stubbed re-scans it and brings the same agents back, which is the other half of the dialog's promise.
- **The user menu's `Settings` item toggles**, `activeView === 'settings' ? 'chat' : 'settings'`. A helper that opens Settings by clicking it will walk a spec *out* of Settings on its second call — and the failure lands somewhere unrelated, because the settings sidebar's `Chats` and the chat shell's `Chats` are both a button named `Chats`. Open the shell only when a settings-only sidebar item (`MCP Providers`) is not already visible.
- **"Ollama is not running" cannot be arranged, and must not be made arrangeable.** `candidateHosts()` probes `OLLAMA_HOST` and then falls back to `127.0.0.1:11434` **regardless** — deliberately, because a packaged macOS app does not see the user's shell — and a sandboxed `HOME` does not change loopback, so the fallback finds whatever real Ollama the developer's machine is running. The **running** path is deterministic: `test.use({ env: { OLLAMA_HOST } })` pointed at a `node:http` fake, which `detect()` returns on before it ever reaches 11434. The fake must serve **both** `/api/version` (`{"version":"0.6.2"}`) and `/api/tags`, and its model ids must be real-shaped (`qwen3:8b`, `llama3.2:3b`, with a `details.parameter_size`) — anything matching `embed` is filtered out by the adapter. The not-running path belongs to `src/main/services/ollamaService.test.ts`, which covers it in both directions.
- **A credential seeded through the UI needs no relaunch.** The "credentials seeded over IPC are stale" gotcha above is about `providers.upsert` called from `page.evaluate`; a credential created by pressing a button goes through `useUpsertProvider`, which invalidates `['providers']`, `['models']` and `['ollama-detection']` — so the next settings tab, the chat-mode form and the Runs-with panel all see it in the same window. That invalidation is itself worth asserting: the Ollama offer row is suppressed by the probe's `alreadyConfigured` alone, and the probe is cached for 15 seconds.
- **The confirm in front of a credential's off switch is decided by two queries, and an unloaded one means "nothing depends on it"** — deliberately, so a dialog cannot appear a beat after the switch has already moved. So a spec that lands on **AI Credentials** in a window where `useChatModes` / `credentialBindings` have never been fetched can legitimately get *no* dialog for a credential that has dependents. Reach the tab the way a user does — the run that creates the chat mode through Settings → Chats warms `['chat-modes']` for the whole window — rather than deep-linking into the switch and asserting on a race (`credential-switch.spec.ts`).
- **Never let a spec spawn a `claude` *turn*.** The Claude engine runs the *user's own* install under their own subscription, so a turn on it bills a real person on every developer's machine and in CI. Choosing the engine, the manifest it writes and the panel it renders are all assertable without one (`claude-engine.spec.ts`); a spec that genuinely needs a turn belongs behind the `make e2e-live` gate with its cost written into the file's header. The one `claude` invocation that **is** allowed is the readiness probe, `claude auth status`, which the panel causes by itself: it runs no turn, logs nobody in or out and bills nothing (`claude-logged-out.spec.ts`).
- **A spec that is not about readiness pins the login probe, over `ipcMain`.** Because the sandbox's answer is `logged_out`, every spec that renders the Claude branch gets the red remedy line unless it says otherwise — which is right for `claude-logged-out.spec.ts` and noise for `claude-engine.spec.ts`. Replace the handler in the app process, **after the last `relaunch()`** (handlers are per process): `cinna.electronApp.evaluate(({ ipcMain }, status) => { ipcMain.removeHandler('local-tools:claude-auth'); ipcMain.handle('local-tools:claude-auth', () => status) }, { state: 'unknown', authMethod: null, subscriptionType: null })`. Pin `unknown` rather than `logged_in`: it is the honest "readiness was not answered", it is the state the install sentence describes, and it fabricates no account. It also means the spec spawns no `claude` child at all.
- **"Logged out" is the sandbox's free gift, and it must not be papered over.** `buildClaudeEnv` passes `HOME` through to the probe's child, and every test has a throwaway one, so a real `claude` reports `{"loggedIn": false, "authMethod": "none"}` (exit 1, answer still on stdout) under it — verified on a machine whose *real* `HOME` reports `"loggedIn": true`, so the arrangement costs nothing and logs nobody out. Two rules follow. Wait for the line rather than reading it on first paint: it is empty while detection is in flight **and** empty again while the login probe is (~300ms), both deliberate silences. And never write an assertion that passes on both `Run \`claude\` in a terminal: …` and `Claude Agent runs on your own Claude Code install, …` — the second is the `unknown` rung, so a spec matching either passes on a probe that has silently stopped answering, which is exactly the regression worth catching. Assert the probe's own answer separately (`localTools.claudeAuth()`) so a degraded probe fails with its reason on it, and assert the Engine column still reads `Claude Code <version>` so "logged out" cannot be confused with "not installed".
- **A hand-added A2A agent is the only agent kind that needs no credential at all**, which makes it the only way to write a spec whose claim is "no LLM provider is configured anywhere". A folder agent's OpenCode launcher refuses before it spawns anything unless a credential resolves a model (`configGenerator`'s `credential_unavailable` / `no_model` skips), so `installFakeAcpEngine` always drags a keyless `ollama` row and a default chat mode in with it. Two `node:http` fakes of ~40 lines each (see the A2A gotcha below) cost nothing and let `providers.list()` / `chatModes.list()` be asserted empty at the end of the run (`human-routing.spec.ts`). A consequence to expect on such a profile: the composer's `[+]` (`Add to chat`) is **absent**, because `hasAnyDestination` hides it for a user with neither a Cinna account nor a provider — the `@` popup is the only capability picker available there.
- **Make a fake agent's reply a function of the prompt it was sent.** A fake that answers a constant proves a turn completed and nothing about what travelled: the catch-up packet could be deleted and every screen assertion would still pass. `human-routing.spec.ts`'s second agent answers with the code only when the code is in its prompt and says `Scribe saw no vault code in what it was sent.` when it is not, so the screen itself is the witness — verified by mutation: `buildCatchUpPacket` returning `null` fails that one step at 30s and nothing before it. The wire is asserted as well (the packet's `[<Agent name>] <text>` transcript line, the earlier `[user] …` line, and the typed text last), because the two fail for different reasons.
- **`window.api.jobs.execute(jobId)` from `page.evaluate` starts no stream, so it can never produce an ask.** The handler creates the chat, the `job_runs` row and the task and returns; the *renderer* is what opens the turn's `MessagePort`, in `useJobs`' `startRun`. Seeded that way nothing runs, no `needs_input` reaches `observeAsks` in `runExecutionService.ts`, no `task_input_requests` row is written and the inbox stays empty for ever — with no error anywhere. Arrange the job over IPC and press **Run** (the job page's `Run`, or `Run this job` on the sidebar row, which runs without navigating). Two agents lost a run to this before `inbox.spec.ts` was written.
- **The inbox list polls every five seconds and nothing pushes it.** `useInboxList` is a `refetchInterval` (gated on `document.visibilityState`, not on OS focus), so a newly parked ask takes up to that long to reach the badge *and* the view — they read one cache entry, so they can never disagree. Wait on the assertion with a generous timeout (20s in `inbox.spec.ts`); answering invalidates immediately, so the way back down needs no extra wait.
- **A fake ACP agent's `{kind:'delay', ms}` is how a task's transient statuses become observable.** The trail `in_progress → blocked → in_progress → completed` has two intervals that are otherwise a few milliseconds wide — the work before the ask and the work after the answer — and sampling for them is a race. Scripting the fake to *work* for a couple of seconds either side of the ask makes both real intervals, which an `expect.poll` (at `intervals: [50]`, not the default ramp) waits for honestly. It is the agent behaving like an agent, not a sleep in the test.
- **Pressing the sidebar tab you are already on is a no-op except from a view that belongs to no tab.** `handleSwitchTab` returns early on `target === sidebarTab` unless `activeView` is one of `TABLESS_VIEWS` — `inbox`, `task`, `cinna-task-run` — in which case it realigns the centre to that tab's own view (`chats`→`chat`, `jobs`→`job-detail`, …) and keeps the selection. So `Jobs` is the way out of the inbox or a task page back to the job it came from, and `Chats` from the inbox lands on the open chat rather than resetting it.
- **A task's status is read with `tasks.list()` / `tasks.get(id)`; `tasks.list()` excludes only archived**, so a `completed` task is still in it. A job's task is found by `t.jobId === jobId` (it also carries `jobRunId` and the run's `chatId`, which is how a run, its chat and its task are tied together in an assertion). Vocabulary in `src/shared/taskStatus.ts`; there is **no status history table**, so a trail is observed by polling, never read back.
- **Live specs**: `test.beforeEach(() => requireLiveKey())`, one model turn, `test.setTimeout` generously, a question whose expected answer is **not** in the prompt text (`12 times 12` → `144`).
- **A block made live by two sources proves neither.** A local agent's ask becomes answerable from the stream's `needs_input` *or* from `useAgentRequests` polling `agent:pending-requests` every 700ms, so a spec that leaves both on passes with either one broken. `run-events.spec.ts` replaces the poll's handler with `() => []` after the last `relaunch()`, which leaves the stream as the only source; the answer still goes through the real `agent:answer-request` and registry. Say which source a spec is about.
- **A fake SSE server must drop subscribers on `res`'s `close`, never `req`'s.** A GET's `IncomingMessage` emits `close` as soon as its empty body is read, so `req.on('close', …)` removed every `/api/event` subscriber immediately: the turn got as far as `POST …/prompt` and then heard nothing, with no error anywhere. Learned on the retired HTTP `opencode serve` fake — folder agents speak ACP over stdio now — and still the rule for any spec that serves an event stream; what showed where the turn stopped was the fake's own request log, which is why `fakeAcpEngine`'s log has the same job.
- **The preload's `console.warn` reaches `page.on('console')`**, with the logged value formatted into `text()` (`[preload] dropped off-contract run event {type: toString}`). To put an off-contract message on a real turn port, swap the channel's listener in main (`ipcMain.removeAllListeners('run:send')` then `ipcMain.on(…, (event) => event.ports[0].start() / postMessage(…))`) and call `window.api.run.send` with your own callback (`ipc-wire.spec.ts`); the retired per-driver send APIs are no longer present.
- **A local agent's answered question shows its answer inside the block, and nowhere else.** The driver persists `Answered: <labels>` as a `tool_result` on the `que_` id. `MessageStream`'s `pairCommandTools` consumes it, and `AskUserQuestionBlock` renders it as the `decision` line under `A question asked`, the way a permission shows `Allowed once.`. `run-events.spec.ts` pins the replayed block showing it: the page contains `Teal`, which nothing else on screen says. Read the stored string from `chat.get(chatId)` parts. The Claude adapter's own `AskUserQuestion` call and its result are folded away too, but only when a `tool_call` named `AskUserQuestion` has the id the elicitation sends as `toolCallId`. `ASKS_QUESTION` sends the elicitation alone, so no spec reaches that fold; its cases are in `src/renderer/src/components/chat/MessageStream.questionEcho.test.tsx`.
- **`ENOTEMPTY: directory not empty, rmdir '…/cinna-e2e-…/home'` is the fixture's teardown, not the test.** After a passing body, `rmSync(sandbox.root, { recursive: true, force: true })` runs straight after `electronApp.close()` and can race something still writing under the sandbox `HOME`; the test is then reported failed with that as its only error and an `error-context.md` that shows fixture source instead of a screen. Seen on two untouched `bare-agent.spec.ts` tests in one of three identical runs. Rerun before diagnosing; it is not an assertion.
- **A teardown that times out on every spec, including untouched ones, can be machine load.** `Tearing down "cinna" exceeded the test timeout` across a whole run cleared on its own minutes later on the same build, while `app.quit()` called inside main quit cleanly. Rerun an unchanged spec before blaming the build.
- **A model reply that stops mid-stream is a keyless credential and a response that never ends.** An `ollama` credential keeps its `baseUrl`, and its chats stream through the OpenAI adapter against `<baseUrl>/v1` — so a `node:http` server the spec owns can answer `/api/tags` with one model and `POST /v1/chat/completions` with a few SSE `chat.completion.chunk` lines and then **hold the response open**. Only the client can end it, so Stop always lands mid-reply, and `res.on('close')` with `!res.writableEnded` is the witness that Stop really aborted the request. Seed with `settings.set('autoChatTitles', false)` so the turn is the only model call, and `relaunch()` after the IPC seeding (`llm-stop.spec.ts`). No vendor host is involved, so `stubLlmFetch` is not needed.
- **Composer and sidebar stop actions have separate accessible names.** The composer uses exact button names `Stop` and `Send`, one at a time in the same place. In an idle chat Send is disabled while the input is empty or the direct agent is refused on readiness. While a turn runs, an empty input or a refused direct agent shows Stop instead of Send, whatever is typed. Sidebar buttons use `Interrupt session`, `Interrupting session…` and `Delete session`. Never locate composer Stop by square SVG: running sidebar rows also contain a square. `e2e/specs/llm-stop.spec.ts` uses exact role/name locators; Enter in the textbox remains the way to send.
- **The chat curtain clones the composer, so find it by role.** On every chat switch — including the first send from the new-chat screen — `ChatTransition` appends a clone of the outgoing view (`.chat-transition-snapshot`, `aria-hidden`, `inert`) whose textarea keeps the same `placeholder` and the sent text, and removes it when its ~260ms animation ends (measured: added 45ms after the send, removed at 310ms). A spec driving a local fake reaches the composer again inside that window, and `getByPlaceholder('Type a message...')` fails with a strict-mode violation naming two textareas, the second holding the prompt. `getByRole('combobox', { name: 'Type a message...', exact: true })` skips the clone. This is what failed `llm-stop.spec.ts` and `a2a-silent-stop.spec.ts` after the curtain landed, and `task-live-attach.spec.ts` (a sidebar chat click, then an immediate fill) until it was found; role queries (`paragraph`, `button`) are unaffected, `getByText` is not. **No spec uses `getByPlaceholder` for the composer any more — keep it that way.** The clone appears only when the curtain *updates*: opening a chat from a page outside `ChatWorkspace` (the task page, the Inbox) mounts the curtain fresh and copies nothing.
- **The composer's name changes while a turn runs.** It is named by its placeholder, and that is `Send a follow-up · Esc Esc to stop` from the moment the turn is streaming, so a `Type a message...` query mid-turn finds nothing — the live composer is the only textarea and it no longer carries that name. `task-start.spec.ts` asserted the idle name right after **Continue** started a turn and failed from the day the running placeholder arrived; assert the running name there (`getByRole('combobox', { name: 'Send a follow-up · Esc Esc to stop', exact: true })`), and the idle one only once the turn has ended.

## Debugging a failure

- **No test downloads the Codex CLI.** The app installs its own pinned Codex on first use (~90 MB); `e2e/fixtures/app.ts` sets `CINNA_CODEX_DOWNLOAD=off` on every launch, after a spec's own variables, so no spec can switch it back on. A spec that drives Codex must set `localAgentsCodexPath` to its scripted CLI (`window.api.settings.set`). Putting the fake first on the sandbox PATH is **not** enough: no spawned session runs the PATH copy, which only detection and "Open in…" see. A spec that forgets fails with a sentence instead of fetching the real CLI and running it under a test's name. A fake that must pass the restricted chat policy advertises `RUNTIME_PINS.codex.versionOutput`, never a literal version.
- **Codex can create its own ephemeral title thread.** The adapter may emit `thread/start` with `ephemeral: true` even when Cinna's `autoChatTitles` is false. Assert conversational continuity using non-ephemeral thread starts and that conversation's `threadId`; do not count auxiliary turns as another chat. `codex-engine.spec.ts` uses a supported-version scripted CLI only for the synthetic policy case, while the installed ACP adapter and policy helper remain real.

1. `e2e/test-results/<test>/error-context.md` — the aria snapshot at failure, with the failing locator. Read this first; it usually answers "what did the screen actually show".
2. `test-failed-*.png` — one per window (main and tray).
3. `make e2e-trace TRACE=e2e/test-results/<test>/trace.zip` — every step with DOM snapshots and console.
4. `[main] …` lines in the run output are the main process's stderr — IPC handler failures log there with `code`, `message`, `detail`.
5. Temporary `console.log(JSON.stringify(await page.evaluate(() => window.api.…)))` to see what main believes; **remove before finishing**.
6. The sandbox of a failed test is kept — inspect `userData/cinna.db` and the agents root on disk.
